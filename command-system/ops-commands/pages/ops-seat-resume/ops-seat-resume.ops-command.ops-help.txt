Put a seat back on the session it was bound to, with its prior context.

WHETHER A SUPERVISOR IS STILL RUNNING IN THE SEAT IS THIS COMMAND'S TO FIND
OUT, never the caller's to know, and it takes whichever act the answer calls
for:

  live   the seat is cycled IN PLACE: `restart` goes into its uncommitted
         file, its supervisor's poll picks it up and arms an idle gate. At the
         next turn boundary the gate SIGTERMs the Claude CLI and spawns an
         iteration resuming the session. The turn is kept — nothing is killed
         out from under it. Prints `queued-on-idle`, because the value clears
         when the restart is ARMED rather than when it fires.
  gone   a detached supervisor is launched on the bound session, hydrating the
         local transcript from the object store where the local copy has gone.
         Prints `revived`.
  SELF   never the immediate signal: `restart` goes into its own file and
         `queued-on-idle` returns at once, so the seat is not killed mid-turn
         and its issuer is answered before it dies.

`--now` writes `restart-now` instead, which the supervisor takes up at once:
it interrupts the turn the agent is in and prints `restarted`. The flag is
`--now` rather than `--force` because `--force` already means something else
here — restart though subagents are working, ending them with it.

A supervisor whose presence CANNOT BE READ is not a gone one: no sidecar, an
unparsable process and an unreadable /proc entry all reach the guard as a LIVE
holder, so the seat is cycled rather than launched over. A handshake that times
out re-probes once and launches fresh if the supervisor has since died, closing
the died-mid-wait race; a live but unresponsive one exits ack-timeout.

`--start-mode` says who launches, the same split `ops seat start` makes.
  `headless` (default)  launches here, and is everything above.
  `interactive`         launches the seat DETACHED and prints the id and session,
                        leaving the front that asked to attach to it. A live
                        holder is TAKEN: SIGTERM,
                        escalated to SIGKILL past the grace window, and polled
                        to exit before anything prints, so two supervisors
                        never race on one session.
It defaults to `headless` where `ops seat start` defaults to `interactive`,
because every caller here launches detached and a default that flipped under
them would start the wrong kind of seat with nothing to catch it.

THE TARGET IS OPTIONAL AND DEFAULTS TO SELF ($AGENT_ID), so a seat queues its
own restart with a bare `ops seat resume`.

WHETHER A REVIVED SEAT TAKES A TURN IS THE CALLER'S TO SAY, and the default is
no. Bare, a gone seat comes back IDLE and reads nothing: a `--resume` on an
empty prompt drives nothing, so Claude Code fills the void with `Continue from
where you left off.`, the model answers `No response requested.`, and the seat
sits there. A revive meant to put a seat back to WORK must say what the work
is, with `--prompt`. A row property does not start a seat.

Do NOT revive bare and then `send`: the send races the boot, the row being
`pending` before the resumed session can receive, and the booting backlog drain
claims the notice. The prompt rides argv, where there is no row to lose.

A FIRST TURN IS FOR A SEAT THAT IS NOT RUNNING, so the launch flags are REFUSED
against a live holder rather than dropped. A running seat has a turn already;
hand it work with `ops seat send`, which reaches a live seat and revives a
stopped one.

Default stdout (TSV, one line):
  <agent_id>\t<name>\t<restarted|revived>
  <agent_id>\tqueued-on-idle        (self-target)
  <agent_id>\t<session_id>          (`interactive`)
