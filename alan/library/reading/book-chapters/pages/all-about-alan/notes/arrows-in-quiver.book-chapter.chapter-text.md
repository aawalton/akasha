
# Arrows in quiver

> Arrows in quiver — Alan's deliberate system for talks and presentations. A set of small conceptual arrows ready to deploy when triggered by specific circumstances, instead of a memorized verbatim script.

For talks and presentations, Alan does not write a verbatim script and try to remember it. He thinks about the topic broadly, builds a quiver of small conceptual arrows, and deploys each arrow when the specific circumstance for it appears.

The talk runs as a sequence of arrow deployments. Each arrow is a self-contained conceptual unit — a point, an example, an argument, a story — paired with the circumstance that should fire it. When the audience asks a question, or the conversation drifts into a related area, or a particular framing comes up, the matching arrow fires.

## Why it works for Alan

The system is effective for many speakers — it generalizes beyond AuDHD. But it is *particularly* well-suited to Alan for two reasons.

### Leans into trigger-based conceptual memory

Each arrow is a concept retrieved by a circumstance-cue. Same architecture as the [text-memorization chains](trigger-based-memory.book-chapter.md#1-text-memorization), scaled up from word-cues to circumstance-cues. Alan's [System B' externally-cued S-R habit learning](automaticity-systems.book-chapter.md#b-externally-cued-s-r-habit-learning--intact) is intact and load-bearing — arrows-in-quiver runs on it.

Verbatim scripts would route through a different system entirely. Alan's memory architecture is well-matched to "circumstance triggers concept"; it is poorly matched to "remember this exact sequence of words". Using the well-matched architecture makes the talk effortless rather than effortful.

### Accommodates statelessness

No verbatim script means nothing verbatim to remember. [Statelessness](aphantasia-mechanism.book-chapter.md#statelessness--only-conceptual-memory-persists) means Alan can't reliably hold the exact phrasing of even a recently-written sentence across the gap between rehearsal and delivery — the recall channel that would carry the sentence isn't there.

The arrows-in-quiver approach bypasses the problem entirely. The arrows *are* the memory; the circumstance fires them. There is nothing to forget that the system depends on. A speaker without statelessness can write and rehearse a verbatim script; Alan can't, and arrows-in-quiver is the alternative that works without that channel.

The mechanism unification — same architecture as text memorization and the agent harness — is captured in [trigger-based-memory.md](trigger-based-memory.book-chapter.md).

## Operating shape

- **Broad topic-thinking up front.** Alan thinks about the topic widely before drafting any arrows. The breadth matters because each arrow has to be ready to deploy from a wide range of circumstance-cues — narrow preparation produces a quiver that runs out of arrows when the conversation goes somewhere unanticipated.
- **Arrows are small.** A single arrow is a conceptual unit, not a section. The smallness lets the talk compose freely; the talk is a sequence of arrows chosen on the fly, not a fixed outline.
- **Circumstance is the cue.** Each arrow has at least one circumstance that should fire it. The cue can be a question, a framing the audience uses, a related topic that comes up, or a state the conversation lands in.
- **Order is emergent.** The order of arrows is determined by which circumstances appear, not by a pre-decided sequence. The talk reorganizes around the audience.

## Trade-offs

- **Lower verbatim precision.** A specific phrasing chosen in advance is harder to land. When the exact wording matters — a legal disclaimer, a one-line quotable framing — the arrows-in-quiver approach has to make room for a separately-memorized fragment, or accept lower precision.
- **Higher in-the-moment cognitive load.** Selecting arrows on the fly costs working memory during the talk. Compensated by the absence of script-recall load, which would otherwise dominate.
- **Quiver inventory has to be enough.** If the talk goes somewhere no arrow covers, there's nothing to fire. The breadth-up-front step is what prevents this.
