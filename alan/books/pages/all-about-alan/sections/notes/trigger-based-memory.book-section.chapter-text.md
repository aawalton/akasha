
# Trigger-based memory

A single retrieval architecture runs across Alan's memory practices: a cue fires, and the cue retrieves the next concept. The chain is **trigger → concept → next trigger → next concept**. Not stored verbatim; not pulled by free recall; cued every step.

The mechanism is [System B' externally-cued S-R habit learning](automaticity-systems.book-chapter.md#b-externally-cued-s-r-habit-learning--intact). System B' is intact in Alan's brain; the deliberate route into it has the [slow-start / higher-ceiling signature](automaticity-systems.book-chapter.md#quantitative-shape--slow-start-higher-ceiling). Alan has built three load-bearing applications on top of it.

## Three domains

### 1. Text memorization

Two techniques in this domain, both running on System B'.

- **Word-triggers-word chains.** Each word in the text becomes the cue for the next word. Memorizing a book is memorizing a long chain of cues; reciting it is firing the chain step by step. Alan has memorized entire books this way, faster than most. Original mention in [automaticity-systems.md → Compensation strategies](automaticity-systems.book-chapter.md#compensation-strategies).
- **Cascading trigger-based text memorization.** Alan's own self-developed technique. The cues nest: a section is triggered by a top-level cue, paragraphs inside it are triggered by section cues, sentences by paragraph cues, words by sentence cues. The structure is a tree of triggers rather than a flat chain. Lets Alan re-enter the text at any level — recover a paragraph from a paragraph-cue without replaying the whole book — and resists the cascading failure mode where one missed word breaks the entire chain.

The two techniques cover different needs. The flat chain works when verbatim word-by-word recall is the goal. The cascading version works when conceptual re-entry matters — recovering meaning, not just the next word.

### 2. Talks and presentations

The **arrows-in-quiver** strategy. Rather than writing a talk verbatim, Alan thinks about the topic broadly and creates a series of arrows — small conceptual units, each ready to deploy when triggered by a specific circumstance in the conversation or audience. The talk runs as a sequence of arrow deployments, not a sequence of memorized sentences.

Effective in general — many speakers use a version of it. Particularly well-suited for Alan for two reasons:

- **Leans into trigger-based conceptual memory.** Each arrow is a concept retrieved by a circumstance-cue. Same architecture as the text-memorization chains, scaled up from words to concepts.
- **Accommodates statelessness.** No verbatim script means nothing to remember verbatim. The arrows are the memory; the circumstance fires them. Alan's [statelessness](aphantasia-mechanism.book-chapter.md#statelessness--only-conceptual-memory-persists) makes a verbatim-script approach unworkable; arrows-in-quiver bypasses the problem entirely.

The system treatment is [arrows-in-quiver.md](arrows-in-quiver.book-chapter.md).

### 3. The agent harness

The same pattern at a higher level of abstraction. System state is the trigger; the next action is the retrieval. The harness is a structure of cue → action chains: "this state means do this; doing this puts the system in that state, which means do that." Alan has confirmed the harness uses this mechanism heavily.

The trigger here is no longer a word or a circumstance — it's the externalized state of the system itself. The retrieval is no longer a concept on its own — it's a concept that selects the next action. But the architectural shape is identical: cue fires, the cue retrieves the next thing, no free recall and no verbatim store.

The system treatment is [agent-harness.md](agent-harness.book-chapter.md) — see specifically the action-sequence-scaffolding component, which is where this architecture lands.

## Why the unification matters

Three observations land together:

- **One mechanism, not three.** What looks like three separate skills (memorizing books, giving talks, running the harness) is one architectural pattern deployed at three scales. The mechanism is System B' running on increasingly abstract cues.
- **System B' is load-bearing.** Earlier framings treated System B' as the surviving habit-learning route. The unification shows it doing much more — it carries the symbolic-token sequences that System D would otherwise carry, the conceptual deployment of talks, and the architectural backbone of the harness. The route that worked got asked to do a lot of work.
- **The compensation for missing System D is bigger than "lists".** [Statelessness](aphantasia-mechanism.book-chapter.md#statelessness--only-conceptual-memory-persists) plus missing [System D action-sequence chunking](automaticity-systems.book-chapter.md#d-internally-generated-action-sequence-chunking--reduced) drives a hard need for external sequence-scaffolding. The harness supplies the scaffold; trigger-based memory is *how* Alan deploys the scaffold without re-paying the System-D cost each time.

## Cue-specificity boundary

The S-R chain trick has a known boundary: it transfers cleanly to symbolic-token sequences and not to motor sequences ([automaticity-systems.md → Compensation strategies](automaticity-systems.book-chapter.md#compensation-strategies)). The unification widens the question — three domains now use the same trick. Where the cue stays "discrete enough" the architecture works; where it doesn't, it fails. The boundary across all three domains is an open probe (the cue-specificity-boundary thread in `/abby`'s backlog, sharpened by this unification).
