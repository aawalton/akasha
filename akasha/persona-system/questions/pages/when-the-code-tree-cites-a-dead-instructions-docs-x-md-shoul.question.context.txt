Quarantine moved every instruction surface out of `~/instructions/docs/`, so the code tree's citations of that path all resolve to nothing — there is no `docs/` directory there at all. At `origin/main` there are **705 such citations across 127 distinct targets**. Each one gets repaired once, and how the first few are repaired sets the pattern for the rest.

Two answers are live, and one is already being taken:

- **Repoint** — the citation becomes `~/instructions/knowledge/<x>.md`, the rebuilt surface. One document, in the perimeter, gated by the door and reviewed against what binds it.
- **Move** — the document is copied into the code tree at `docs/<x>.md` and the citation made relative. `project-17353` has done exactly this for `ops-namespaces.md`: absent from `origin/main`, added on the branch, root `CLAUDE.md:66` rewritten from `~/instructions/docs/ops-namespaces.md` to `[docs/ops-namespaces.md](docs/ops-namespaces.md)`.

It is one file, not a policy — the branch adds no other document to `docs/`. That is why it is worth asking now rather than after it merges.

What makes it hard to see: after the move the citation resolves, so a sweep for dead paths correctly finds nothing. The estate then holds a live copy in the code tree, governed by nothing this perimeter reaches, beside a quarantined copy — with no surface saying which is the original. In this instance the copy is one an ingestion has since judged not worth rebuilding at all: its census is stale (it names 47 of 89 command paths, and one, `buildkit`, retired in #10098), and among the 42 it never names are `finding`, `ask-alan` and `browser-test`, which the curated system prompt tells every headless seat to run.

Nothing is blocked this minute, but every ingestion seat meeting a dead citer faces this choice, and they meet it constantly — it has come back in six hand-offs tonight.
