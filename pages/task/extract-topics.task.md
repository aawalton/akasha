# Definition

- **Extract topics** — one note or finding, turned into the topics it needs and the questions it leaves open.

# Loop

1. **What you take next.**
   - **Choose** the next one yourself and say why before you open it. Asking spends Alan's turn on a call already delegated, and working a list in order hides the choice entirely.
   - **Prefer** a subject the standing topics already touch. A note landing wholly in new ground builds tree without testing any of it.

2. **The topics it needs.**
   - **Name** the topic in the plainest words that carry it, never in the words the note reaches for. A note's vocabulary is the vocabulary of the session that made it, which reads as precision from inside and as jargon from everywhere else.
   - **Write** the definition as you would say it aloud to someone who has not read the note. The note is where the term gets earned; the topic is where it gets found.
   - **Put** every departure, absence and constraint in Design, and leave the definition saying only what the topic is about. A finding written into the definition reads as precision, and it stacks the name, the subject and the reading in one line where none of the three can be changed on its own.
   - **Run** without asking wherever no topic is being minted: hanging a question on one that already stands, taking a thread out of a note, repointing a link the departing queue left dangling.
   - **Mint** what the questions need without asking, and tell Alan what you made rather than what you weighed. Minting is cheap where moving one afterwards is not, so a split the Questions bound forces is made rather than deferred.
   - **Run** [define-domain-structure](define-domain-structure.task.md) instead where the subject turns out to need a domain, per [Read Or Recorded](../page-type/book.page-type.md#read-or-recorded).

3. **The questions it carries.**
   - **Hang** each open thread on the topic it bears on, never on the topic it happened to be written under.
   - **Split** the topic where its Questions section runs out of room. The bound reports granularity; it is never a reason to leave a question out.
   - **Drop** a thread the note itself already answers. Several are marked answered in place and carrying them across revives them.

4. **What the note is left holding.**
   - **Take** the thread out of the note once it stands as a question, so the claim that the notes hold no queue becomes true rather than aspirational.

# Invariants

- **A note needing no new topic is not a failed run.** The tree was already right there, which is the only evidence that it is right anywhere.

- **The run ends where the material does, not where a note does.** Nothing but Alan starts this loop, and once it is running you open the next note in the same turn and keep going until every note and every finding is worked, or something blocks you. A finished note and a clean report read from inside like a place to stop, and stopping there spends one of his turns restarting what was already running.

- **The tree is built by open questions, never by what is already settled.** A note's settled structure earns no topic of its own: the notes are already the table of contents, and a topic minted for a subject nobody is still asking about buys a second one. Every note and every finding is worked before anything else in the material is.

- **This is a hand migration, and the cost per note is the design rather than a defect.** A note is read whole before it is rewritten because the gate charges that, and it is the same reading the extraction needs anyway. A run that felt slow is not evidence for a script.
