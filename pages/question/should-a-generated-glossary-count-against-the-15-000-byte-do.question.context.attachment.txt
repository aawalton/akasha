A domain's `# Glossary` is generated — one bullet per child domain, each carrying that child's `# Definition` verbatim. No author can edit it. But it counts against the same 15,000-byte ceiling as the authored prose, so a domain with many children has its own authored half squeezed out by its children's definitions.

Two domains are there now:

- `domains/knowledge.md` — 14,681 bytes, 73 generated bullets, 319 bytes free. The next knowledge document lands only if its definition fits in 319 bytes; the one after cannot land at all.
- `folders/code-repo.md` — 14,984 bytes, of which 7,986 is 32 generated bullets against 4,462 of authored routing. One child domain from unwritable.

It has already cost content. Commit `df9ac7ca` landed a child domain and put `code-repo` at 15,096 — over. The next commit, `68b9ec03`, is titled "shorten the definition to the length its parent's glossary has room for": a child's own definition was cut until its parent fit. `token-ceiling.ts`'s docstring names "a byte count deciding what a corpus says" as the thing it exempted review records to avoid, and that is now what it does, one file removed.

`domain.schema.md` already says the generated section is uncapped, because a cap "over a derived set would refuse a corpus for the children it has" — so the schema and the door disagree, and the door wins.
