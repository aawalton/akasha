Verified in a real workbench: the bar is always visible, spans the panel (299px against 299px), sits at the top, has no close button, takes focus when you select the panel, defaults to Filter mode, and Escape clears it. The gate passes C3-C6, 8/8. The one gap: VS Code's async tree only filters nodes it has fetched, and Domains opens with one fetched row (global, collapsed). Proved it by pressing Expand All first, after which the same word correctly narrows 40 rendered rows to 17. The Explorer avoids this because it owns an ExplorerFindProvider; extension-contributed trees have no such seam. Fetching everything up front is not free: 2017 documents declare a domain-slug, so that is ~2017 extension-host round trips per read, on panels that now re-read whenever the repo is written. Cheaper alternative: the ops extension already holds the whole tree in memory from one 'ops' read, so handing it the bar's pattern and letting it return matches plus ancestors searches everything in one in-memory pass. That is a small new API seam on top of the one just built. Nothing is promoted; your editor is untouched.
