# Definition

- **How Many Checks I Run** — how many automatic checks I keep, against what the trade normally keeps

# Design

In two decades in tech, the normal pattern I saw for checks was a handful, three to twelve, almost all external packages like typecheck and eslint, with maybe the occasional custom linter rule.

This year, AI coding ten hours a day sustained, I found it so easy to create custom checks for my specific failure cases that I ended up with about a hundred total.

Most of mine are vendored or custom rather than external packages.

# Questions

What the hundred actually cover, and which failure case each one came from, is not catalogued.

Abby's reading: cheap custom checks are what turned preventing a category of wrong from a decision into a routine. What the practice was before checks got cheap is unwritten.
