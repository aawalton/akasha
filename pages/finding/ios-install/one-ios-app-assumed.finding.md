# Claim

`ios-install` is named as though Alan's phone runs one iOS app, and the code repository holds several — some of them for other people.

# Evidence

The domain's definition reads "a change becoming part of the app on Alan's device, through the build that carries it", and its slug claims the whole of `ios` for that one app.

`packages/` in the code repository holds `alanwalton`, `atlas-app`, `audhdalan`, `smilingjenny` and `temper` beside each other, and `domains/folders/` carries a domain for several of them. In akasha on 2026-08-27 the same fact stands as `native-shell/`, which holds `alanwalton`, `atlas` and `smilingjenny` side by side — three iOS shells, one domain slug. Alan ruled on 2026-08-12 that a bare `ios` prefix cannot stand for his phone for this reason, when it was proposed as the name of a notification domain; that name became `alanwalton-ios-notification` — `pages/domain/alanwalton-ios-notification.domain.md` still carries it — and this document, now `pages/domain/ios-install.domain.md`, was not moved with it and still reads `ios-install`.

What the domain says about builds and installs is unaffected. What is in question is the slug and the definition line, which between them read as though there were one iOS app to install.
