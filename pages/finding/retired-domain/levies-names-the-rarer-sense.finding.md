# Claim

`domains/retired/levies.md` describes the rarer of the word's two senses and prescribes a replacement that would be wrong in most places `levies` actually stands.

# Evidence

The record reads: "**Levies** — including a thing among the set that runs; now written as includes."

That sense is real and matches `tasks/projects/build-singleton-deploy.md` and `build-parent-deploy.md`, both "levies the `tools/` suite among its checks".

The dominant sense is imposing a bound or an obligation, which "includes" does not translate: `tasks/lead/define-definition.md` ("both levied by `tools/document/schemas/domain.ts`... `domain.ts` levies both directly") and `tasks/lead/define-domain-structure.md` ("a harder bar than any ceiling the schema levies"). The tooling carries the same sense in `tools/rm.ts`, `tools/mv.ts`, `tools/document/check.ts`, `tools/document/schemas/domain.ts`, `tools/document/schemas/file-kind.ts` and `tools/governs.ts`.

So the record retires one sense of a two-sense word, describes only the rarer one, and names a replacement that is wrong for the commoner one. A seat obeying it would write "the schema includes a harder bar", which is a different claim.

`domains/retired-domain.md` requires the definition to name the sense the word had. This one names a sense it had.

Filed rather than rewritten, because saying what the second sense should become is a naming decision. Found during project #18012.
