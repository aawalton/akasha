# Claim

A retired entry can be written before the change that makes its replacement real, and nothing tells the difference afterwards. `retired-domain.md`'s Design asks that a definition name the sense the word had and what replaced it, which reads as satisfied by naming a replacement that does not exist yet. An entry in that state instructs every reader to sweep toward a word the running system does not use, and reads exactly like one recording a finished change.

# Evidence

`domains/retired/wake.md` reads "a message that earned the start of a stopped seat; now any message starts one". No message starts a stopped seat. The project that would make it so, #18011, came back on 2026-08-06 at `understand` with nothing written, and its scope was measured at 204 code files carrying the wake family plus a status union.

The corpus's own `wake` sites are all honest and would each be made false by obeying the entry. `tools/hooks/block-headless-halt.sh` describes the wake-source mechanism, which is live and refusing headless turn-ends today. `domains/tasks/general/loop.md` uses the platform tool's own name, `ScheduleWakeup`. `domains/tasks/archivist/review-documents.md` means nobody is awake to disagree. So the sweep the entry asks for would make the harness lie about a mechanism it runs.

The opposite act stands beside it as the control. #18047's seat swept 18 of 21 `estate` sites, could not reach the last three because they mirror a copy in the code repo, and deliberately did not write `domains/retired/estate.md` — on the stated grounds that while a site stands the entry would promise rather than record. Same judgment, made at the point of writing rather than after.

WHAT I DID NOT MEASURE. Whether any other standing entry is in this state: I checked `wake` because #18011's hand-back put it in front of me, and read no other entry against its running system. Nor did I measure how a reader could tell — the difference between an entry recording a landed change and one promising an unlanded one is not visible in the file, in the schema, or to any check that runs today, and I did not look for an instrument that would make it visible.

Filed rather than repaired because the repair is not obvious: the entry could be withdrawn until #18011 lands, or reworded to name the sense without asserting the replacement is live, and which is right is a question about what a retired entry is for.
