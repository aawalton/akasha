# Claim

Four lines are shared between two live tasks with no original to point at. `guided-close-read.md` and `review-instructions.md` carry stage 1's Read bullet and stage 3's name word for word, and the List enumeration, the Run bullet and the Judge bullet differ by a clause or two words. Both are tasks a seat is dispatched to, so cutting from either leaves that task's stage without its step. Single Authority's tolerable case is a copy with a visible original; here there is none.

# Evidence

Raised by a review-instructions seat on `domains/tasks/alan-harness/guided-close-read.md`, which landed five commits on that document and would not touch this: it is not a call a line-by-line reading can make.

The fork it stated: either the shared procedure gets one binding site the two tasks stop restating, or a task document is allowed to carry its own copy of a step.

I did not diff the two documents myself.

The same reviewer flagged a related instance it deliberately kept: `guided-close-read.md`'s "`ops instructions governs --file-path <p>` names both" earns less than it looks, because `ops instructions read` already returns the whole governing set unasked. It did not cut it because the identical sentence stands in the sibling, and cutting one side alone would leave two tasks giving different accounts of one stage. That is the same fork in miniature.

Not measured: how many other line pairs are shared across the two, or whether any has already drifted apart.
