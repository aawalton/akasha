# Claim

`domains/code-comment.md` admits only nine machine-parsed comment forms. The whole of `tools/` is written the other way, including the file the body-move task names as its exemplar, and including the one marker without which a verb does not exist. A rule and the tree beneath it disagree, and the disagreement is not a drift that will settle on its own.

# Evidence

Raised 2026-08-13 by the seat moving the `contacts` bodies, which declined to settle comment policy from inside a namespace move and handed it up.

The No Code Comments rule landed 2026-08-13 at 12:40. `tools/commands/oauth/list.ts`, which `domains/tasks/ops/move-command-bodies.md` names as the exemplar every body seat reads first, landed at 16:16 — three and a half hours later — and is mostly prose header, as is every file written beside it.

`// command:` is the sharper half. `tools/ops/declared.ts` reads that line comment to know a file under `tools/commands/` is a verb at all, and it is not among the nine admitted forms. A file without it vanishes from the CLI. So the rule as written refuses the marker the command system runs on.

The prose headers are the wider half, and they are not obviously wrong: that domain's own Design asks a comment to be explanatory rather than binding, which is what those headers are. But there are several hundred of them now and the rule admits none.

This needs Alan's ruling rather than a repair — either a tenth form for `// command:` and a carve-out for what `tools/` does, or a judgment that the tree is wrong and a plan proportionate to its size. Every body seat now running is following the exemplar, so the tree grows in the rule's despite while this stands open.
