# Claim

One fact — this file is generated — is spelled three structurally different ways in this domain's Design and several more in the instruments around it, and the two main tests are nearly disjoint, so none can simply be dropped.

# Evidence

Measured 2026-08-17, over the 14222 files the domain's `code-path:` reaches in the code repository.

Design now names three tests: a `GENERATED` header in the first five lines, a path that says generated, and a fixture path. **437 files are set aside by one of the first two, and only 19 by both** — 257 by the header alone, 161 by the path alone, with 265 more under `__fixtures__`. The two overlap on 4% of what they cover, so dropping either puts hundreds of files back in scope rather than tidying a redundancy.

The headers do not agree with each other either. Four wordings stand in the tree: `# GENERATED by @shared/fizz-compiler from the .spec.ts beside this file`, `// AUTO-GENERATED — do not edit by hand. Regenerate with: bun ops check-deriver-barrel`, its producer-barrel twin, and `# DO NOT EDIT — generated by scripts/generate-dockerfiles.ts`. `DECLARED` in `tools/code-comment/tree.ts` is case-sensitive on `\bGENERATED\b`, so a header saying the same thing in lower case is invisible to it.

The same conventions are encoded again elsewhere, independently. `CHECK_EXEMPT_DIRS` in `packages/shared/graph/producers/src/lib/constants.ts` holds `__fixtures__` and `generated` as its own set. `packages/infra/checks/src/checks/check-generated-suffix.ts` carries `PRODUCTION_PARTICIPLES`, a list of ten-odd words for the same idea.

Not measured: whether the 161 path-only files could carry a header cheaply. That is the question that decides whether the path test can go, and it turns on which generator writes each of them.
