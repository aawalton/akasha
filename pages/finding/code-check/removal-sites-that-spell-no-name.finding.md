# Claim

A package's name is not the only thing in the code repository that refers to it. `PENDING_CURATION_SIZE` in `packages/infra/checks/src/lib/ast-unused-coverage.ts` is held exactly equal to the length of the list it guards, so deleting an entry leaves the constant one high — and because it is a count rather than a mention, no search for the package's name can find it. Every removal in this initiative has met at least one site that spelled nothing.

# Evidence

Found by #19203, removing three packages the boundary reading ruled dead.

Four sites per package are reachable by name: the directory, the workspace entry in `package.json`, the `ast-unused.config.json` entry, and two rows apiece in `bun.lock` (regenerated by install rather than edited).

The fifth was not. `PENDING_CURATION_SIZE` is asserted equal to `pendingCuration.length` in both directions, so headroom cannot absorb a deletion. Dropping `@shared/pages-rollup-spike` left it one high and branch CI refused. It reads 196 now.

#19202 met the same class of problem from the other side: a name-based sweep that missed the workspaces line. The generalisation is that a removal has to be verified by an instrument that recomputes, never by a search for the name — a count, a length assertion, a ratchet or a fixture total all refer to a package without spelling it.

The three removals still in flight in this initiative are `@agents/messages` (#19204), `@books/book-of-everything` (#19202) and `@temper/shared-capture-validation-host` (#19212). Each should be checked against a recomputing instrument rather than a grep before it is called done.
