# Claim

Binding ids in the design-system carry a layer-ish prefix convention (e.g. conventional.toggle-shortcuts, house.*) that is not stated or enforced anywhere, so it drifts per registrant across the four apps that now register against it.

# Evidence

Parked during #15855/#15866; filed now rather than left in prose. Described as an Ubiquitous Naming gap on a surface four apps now register against. Proposed resolution: decide the rule, state it in the standard doc and package CLAUDE.md, and align existing ids. Noted that binding ids are also the palette's fire-all key, so a rename is behaviour-adjacent rather than cosmetic (see #15900's duplicate-id case). Described as small, owned by the filer, decide-by-default. Project #16107, status someday_maybe, live-on: deploy, domain design-system.
