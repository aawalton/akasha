# Claim

A seat booted on `build-singleton-commit` holds two rules that point opposite ways on one case. `domains/role.md`'s Adjacent Repair says "Land the repair you find, whoever owns the document it sits on"; this document's stage 3 says escalate a failure you did not cause rather than fixing it. A developer watching a check fail on a document it never touched meets both. They reconcile on a distinction neither states — whether another seat is mid-write.

# Evidence

Raised by the review-instructions reading of 2026-08-07, which named the reconciling distinction — whether another seat is mid-write — and did not land it, because the clause would have to go on `domains/role.md`, in a domain's Rules, which Every Changed Line reserves to Alan.

Verified myself: `domains/role.md` carries Adjacent Repair with that wording, and it is in the boot set of every seat that runs a task.

Fifth finding this run standing behind Every Changed Line with no escalation route open to the seat filing it.
