# Claim

Two documents hold the same derivation of the `ops` command list in nearly the same words: `refusals/command-declaration-dropped.md` and the header comment of `tools/commands-retired.txt`. `domains/agent-harness.md` **Single Authority** binds each claim from exactly one document. No schema governs that header, and it is the one place a reader who never meets the refusal learns the rule.

# Evidence

Filed by the seat dispatching the 2026-08-15 `review-instructions` reading of `refusals/command-declaration-dropped.md`, from that reading's hand-back. That reading cut neither, on the two grounds the claim carries.

I read both myself. The refusal says the list "takes two forms: a file directly under `tools/` carrying an `export const tool` block is a command, and so is one under `tools/commands/` carrying an `export const summary`, whose command is its path below that directory spoken with spaces". The header says "a tool directly under `tools/` carrying an `export const tool` block is one, and so is a file under `tools/commands/` carrying an `export const summary` — its command being its path below that directory spoken with spaces". Both open by saying the set is derived rather than written down.

Not measured: nothing here searches for a third site, and nothing here weighs a reader who meets the header against one who meets the refusal — the two arrive in different acts, which is part of why both were written.
