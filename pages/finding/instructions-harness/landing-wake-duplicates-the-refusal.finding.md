# Claim

The wake sent to every reader of a landed surface now carries the same remedy the identity hook gives that reader at its next tool call, so what the message buys is only the interval between the landing and that call — and whether that interval is worth a message per reader per landing turns on a ratio nobody has measured.

# Evidence

Found 2026-08-05, after `c6527341` repaired the collision between the hook levying the moved list and the wake naming a shell command the same standing refuses.

Both now name the native `Read` of the whole file at an absolute path, and the hook's refusal names it too. A recipient that ignores the message meets the identical instruction at its next act, and the hook reaches readers the notifier cannot: an unreachable mailbox, a seat that has ended, a queue nothing drains. In that interval the seat is refused every tool, so it can compose but not act — what the wake saves is tokens spent composing against text that went, never a wrong act taken.

Against that, each landing sends one message per stale reader. Two landings on `domains/agent-harness.md` and `domains/domain.md` within one hour woke eleven readers and then five. `ops seat list` reports `running`/`live` and an `io` column that read `not-applicable` for every seat asked, so the split between readers mid-composition and readers idle was not answerable from it.

One case is recorded: a seat pinned to `roles/lead.md` received the wake and the refusal in the same turn, read the file, and took nothing from the message that the refusal had not already given it.

What would settle it is that split, measured over a run of landings.
