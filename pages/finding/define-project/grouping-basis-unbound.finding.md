# Claim

Nothing tells a lead what makes a set of projects one parent. The insight is bound one application over — `build-parent-deploy.md` stage 1's "Two children touching the same files is not a dependency" — and applied to ordering rather than to grouping. Grouping by the surface a set of rows shares yields a parent whose children share no cause and whose verdict can only be written as a list.

# Evidence

A standing ruling of 2026-07-27, held in `dirty/skills/agent-harness/rulings/rows.md` and reached by an ingest seat emptying that source. Kept verbatim at `dirty/maybe-keep/skills/agent-harness/rulings/rows.md`; filed here because that copy is queued for its own sweep.

`domains/tasks/lead/define-project.md` stage 3 refuses three bad reasons to add a child — "scope is the only reason to add another — never tidiness, separation of concerns, or parallelism" — which governs DIVIDING one project. Grouping is the inverse operation, and the same document's Invariants grant it unguarded: "Combine, split, sequence and close as freely as the work needs."

`domains/tasks/projects/build-parent-deploy.md` stage 1 carries the underlying insight for a different act: "Order the children only where one's result would invalidate a sibling's work... Two children touching the same files is not a dependency." A shared surface is not a real relation — said about ordering, and about nothing else.

The discriminator the ruling offers, *does one change close all of them*, appears nowhere. Swept all of `domains/` for `combine|fold|absorb|consumed|duplicate|merge|covered by` case-insensitively.

A TRAP, checked rather than assumed. The source calls this "substrate", which cannot be used: Plain Or Declared requires a coined word to be declared as a domain, and `domains/retired/substrate.md` holds the slug — `retired-domain.ts` says `domain-slug-unique` "refuses a live domain reclaiming that word". The retirement does NOT falsify the ruling: it retires the sense "the model's own default pull", and a retired domain retires one sense only.

Duplicate check, run as its own call: `rg -uuu -il "group by|grouping|shared surface|one change close|substrate"` over `~/memory/findings/`, twelve files, none of them this.

NOT MEASURED: whether any live parent is grouped this way. The source's specimen — four exit-code rows sharing an exit code and no cause, and a git/Authority group — is one reading of one drain and I did not re-measure it.
