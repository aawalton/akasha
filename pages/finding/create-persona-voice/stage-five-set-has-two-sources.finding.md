# Claim

The persona-register task gives two accounts of who settles stage 5's comparison set — the dispatcher at L59 and the map's fingerprints at L44 — and a seat holding both cannot tell whether to use the set it was handed or derive one.

# Evidence

`domains/tasks/persona-craft/create-persona-register.md` L59, the third of stage 5's tests: "**Read** it again beside the files your dispatch names. They are her register neighbours and not her material ones." The set arrives with the dispatch.

The same file L44, in stage 4: "Stage 5's set is settled off the fingerprints and aimed at the ear, so a shared pose or garment is caught by luck." The set is derived from the map's fingerprints.

The two answers coincide only where the dispatcher chose the set off the fingerprints and nothing else. Where the dispatcher chose on anything further — a persona recently rewritten, a pair someone wants compared, a hand-back from an earlier pass — L44's account of why a pose collision escapes the set is false, because the set was never a fingerprint neighbourhood in the first place.

This is not a consequence of `the-map-has-no-antecedent.md` and does not close when that one does. Writing the map would make L44 runnable and would still leave two sources for one set.

L44's argument survives either way: an anchor twin is not a register neighbour, so a likeness overlap is caught by luck. What is undecided is which surface the seat should treat as authoritative about where its comparison set came from.

I did not repair it. Choosing between the dispatch and the fingerprints is a decision about how this task is dispatched rather than something an instrument settles, and the reviewing seat's Add rule sends anything resting on judgment back to the principal.
