# Claim

Elaine's points source is defined as an overwritable timestamp rather than a durable per-prompt event, so it cannot rescore her history when her source or bar changes, and nothing yet declares the residual Alan accepted on 2026-08-12: a wake or auto-compact continuation can be counted as one of his prompts.

# Evidence

Project #18825, domain persona-points-source, status awaiting_lead_definition, live-on deploy. No initiative field. Not yet started.

Objectives: (1) every prompt Alan authors to a persona should be recorded as a durable event, seen by the hook firing on both a terminal and Remote Control — a timestamp each new prompt overwrites is not a record; (2) the record should be able to rescore a persona's history as far back as it reaches, since points rescore whenever the source or the bar changes and a running counter cannot serve that, so each event should carry its own time; (3) the count should be a kind of source rather than Elaine's alone — her domain document should hold that a marker names a kind of source rather than whose it is, so any persona may come to declare this one; (4) Elaine's domain document should name this as her source, since that is where a persona's source is settled, and hers today asks for a count of Alan's messages that nothing can read; (5) Elaine's row should carry the rule naming it and no longer be declared unable — that declaration stands only because nothing has computed her, and goes once something does; (6) the classifier's residual should be written where whoever reads the count will meet it — Alan accepted it 2026-08-12: a wake or an auto-compact continuation can be counted as one of his prompts, and unrecorded it reads later as an unexplained discrepancy; (7) how far back the source reaches should be stated — it begins the day it lands, so Elaine's count starts from nothing, which is the source's reach rather than a fault in it.
