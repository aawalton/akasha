# Claim

The routing between the initiative and theme tasks runs one way: `define-theme.md` carries a bullet sending a seat to `define-initiative.md` where a single initiative would close the gap, and `define-initiative.md` carries no bullet sending one the other way where a theme is wanted and none stands.

# Evidence

Measured 2026-08-11, on a `review-instructions` reading of `domains/tasks/definer/define-initiative.md` dispatched from `review-documents`. The reading raised it and declined to add the missing bullet.

Stage 2's **Name** child on `define-initiative.md` covers only a theme that already stands — it names the theme in the `theme:` key. Nothing in the document reaches the case where a theme is wanted and none exists.

Why the reading left it: `domains/tasks/archivist/review-instructions.md` admits Add only "where an instrument settles what it should say", and calls it "the one act here that grows what every reader pays for at boot", sending anything resting on judgment back to the principal.

It may well be deliberate. A seat reaches `define-initiative` because a definer has already decided an initiative is what is wanted, so the reverse route may have no traveller. Nothing in either document records that either way.

Not measured: whether any run has stalled for want of the reverse route, or whether the same asymmetry stands between `review-initiative.md` and `review-theme.md`.
