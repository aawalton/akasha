# Claim

Of 187 sessions in one day where what a verb, gate or check does was load-bearing, 8 asserted it from the source without running it; the seat that took that measurement then did it twice more, in the two cases it filed as proof that a help text lies.

# Evidence

Measured over session transcripts on this workstation for the day to 2026-08-05, swept with `find
~/.claude/projects -name '*.jsonl' -mtime -1`: 243 sessions swept, 187 in which machinery truth
arose, 8 in which a seat asserted what a verb, gate or check does from its source without running
it. The sweep must recurse — 91 of the 243 sat a directory below a parent transcript, and all 8
failures were among them, so a one-level glob returns zero over a partial denominator.

The 8 track tool grant more than disposition. 7 of 17 first-cut candidates held no Bash tool at all
and could not have run anything. One main-thread seat logged 924 machinery invocations against 232
source reads, and in every session that ran first, the first run precedes the first source read.

The two counterexamples, re-run on 2026-08-05:

`ops instructions rm --help` prints "THIS IS NOT rename or move, and `mv.ts` is", and `tools/mv.ts`
exists. The `rename.ts` wording it was filed against was replaced in `48f59bef` at 2026-08-04
05:38 — a day and a half before the swept day — so what was quoted as standing had already been
repaired.

`ops project check --help` states, above the line quoted against it, that "every check step page is
materialized when the pipeline is triggered, and the filter the flag drove runs only against a
workflow with no step pages". `applyStepLevelClosureFilter` was read as falsifying that help; the
help already names that filter and says why it does not bite. Which is true needs a pipeline run,
and none was made.

`ops` composes each help block itself and prints the tool's own beneath it, so running it establishes
that the verb name resolves and is wired to the tool named. Reading a `const HELP` literal in that
tool establishes neither.
