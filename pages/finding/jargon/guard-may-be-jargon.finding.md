# Claim

`guard` is written across the domains in two senses and no domain declares it, so a reader meeting it cannot take a plain sense and be right.

# Evidence

Noticed on 2026-08-10 while drafting the `Do The Work` rule for `domains/code-check.md`. The draft leaned two aid sentences on `guard` meaning a check whose population renews, which no reader could have recovered from the word. The aids were rewritten without it and the rule landed as `15dccb09b`, so nothing turns on this — it is the word that is left.

THE FIRST SENSE, a mechanism standing between a mistake and production. `domains/code-check.md:28` reads "what it guards, what that guarding is worth". `domains/agent-governance.md:13` reads "A live path nothing guards is a gap". `domains/tasks/code-harness/review-check.md:23` reads "guarding something imagined". Two entries on `domains/lists/unresolved-checks.md` use it the same way, one naming a check's "guarded set".

THE SECOND SENSE, a construct in the source. `domains/folders/pages-system.md:25` reads "an `eq` on an ordinary attribute passes the guard", which is a precondition that raises, not a check on a change. `domains/document.md:17` reads "A guard annotated with what prompted it never says what it enforces", and that one is about an assertion in code.

Three registered checks carry it in their own names — `check-git-guard-both-forms`, `check-guard-reach`, `check-guarded-resolve` — so the code spells it too. Against `domains/jargon.md`, that changes the price of the work rather than the verdict, and how widely it is written says nothing either way.

WHAT IS NOT ESTABLISHED. Whether a plainer word covers both senses, or whether the two want different words. I did not test a replacement against any site, and I did not read the three checks to see which sense their names carry.
