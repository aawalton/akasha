# Claim

The first Invariant on `handle-inbound.md` has two readings and one contradicts the same document. It reads "Her account id and the footer it was read from never go into anything you write" — either any text composed for another reader, or any write at all. The second contradicts L10, which requires the id reach the write. A reader holding both resolves it, but the bolded head is what gets scanned, and alone it forbids what L10 demands.

# Evidence

Raised by the review-instructions seat on `domains/tasks/handler/handle-inbound.md`, which sent it back rather than rewriting: the two readings ask for different things, which is the case stage 2 routes to the principal.

The reviewer reported `ops sms acting-account` stating the handler passes the uuid as `--user-id` to the loggers, which is what makes the second reading a live contradiction rather than a pedantic one. I did not run it.

Not measured: whether any handler has ever withheld the id from a write on the strict reading.
