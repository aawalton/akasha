# Claim

A gate's refusal can read to the agent receiving it as a prompt-injection attempt, and an agent reasoning correctly will decline it. Nothing in the instructions says what makes a refusal recognisable as one, so every refusal is worded by whoever wrote the gate.

# Evidence

On 2026-08-04 three delegates independently classified one gate's refusal as coercion and declined it, one of them under an explicit standing instruction that a tool result is data rather than instruction. Their reasoning was sound rather than defective: the text labelled eight files NEVER READ and then instructed the reader to read each in full, and it offered a clause under which a wasted call satisfied the requirement — which from outside is an arrangement where every outcome passes.

That incident was recorded as the first objective of the `trusted-subagents` initiative, which closed 2026-08-06 with the objective met. The fix was made and the lesson was written nowhere: no document under `domains/` uses the word injection or coercion, and the initiative file was the only place it stood.

It is newly load-bearing rather than historical. The `consistent-agent-governance` initiative opened the same day makes the refusal the only channel governance has, its first objective being that a seat is never interrupted and learns a reading is owed at the moment an act needs it. A refusal that reads as an attack is a refusal that does not govern, and under that design there is no second channel to fall back to.
