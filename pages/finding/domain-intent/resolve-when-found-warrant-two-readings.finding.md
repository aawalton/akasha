# Claim

The warrant on `## Resolve When Found` reads two ways and only one of them is true. `Nothing re-reads an entry, so one that came true and stayed sends someone at a gap already shut.` Read as no instrument watches an entry for coming true, it holds. Read as written — that nothing reads an entry again — it does not: `pages/task/lead/verify-handback.md` stage 3 reads one at every hand-back. The two readings ask a reader for different acts.

# Evidence

`pages/domain/domain-intent.md` as it stands on 2026-08-22 carries one rule, `## Resolve When Found`, whose warrant is the sentence above. I read the file whole.

Things do read an entry again. `pages/task/lead/verify-handback.md` stage 3 carries `**Resolve** the intent entry on the domain where this project passing makes it true`, which reads the entry at the moment a project passes. `pages/task/aine/settle-domain-layer.md` line 58 rewrites an entry on a persona and cites this same rule.

The narrow reading holds. Grepping `tools/` for `# Intent` returns `tools/lib/project-worker-gate.ts`, which reads the quoted criteria on a project document rather than a domain's entries, and no check reads a domain's `# Intent` at all.

Raised by the review-instructions reading of `pages/domain/domain-intent.md`, finished 2026-08-22, at its line 3, which kept the warrant and sent the wording back. `pages/page-type/domain.md` Every Changed Line reserves a line in a domain's Rules to Alan, and the warrant is already at 96 characters against the 100 `pages/domain/domain-directive.md` allows, so a rewording has almost no room to grow.

Not measured: whether a reader has in fact taken the wide reading, and whether any wording inside 100 characters carries the narrow one.
