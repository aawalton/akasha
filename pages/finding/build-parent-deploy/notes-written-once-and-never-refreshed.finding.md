# Claim

The project document's `# Notes` are written once, at stage 1, and never again — while `domains/project.md` binds the seat to rewrite them to where the project stands now, and the lead verifies from them. Two later stages say "record its verdict" without naming where.

# Evidence

Measured 2026-08-06 on `domains/tasks/projects/build-parent-deploy.md`, whose sequence runs eight stages.

Stage 1, line 23 — "**Write** the plan and the order the children run in into the `# Notes` section of the project document, at `projects/<seq>.md` in the memory repo, which your lead verifies from."

No later stage writes to `# Notes`. Line 39, in a middle stage, says "run each one and record its verdict" without naming where the record goes; the reading reports a second such phrase at stage 6.

`domains/project.md:18-20` binds Current State — "**Rewrite the Notes section to where the project stands now, rather than appending to what it said.**"

So a manager following this sequence literally hands the tree back with a stage-1 plan standing as the record, seven stages stale, and the lead verifies from that.

No slice can reach this. The defect is in what the sequence never says, which is invisible to a walk that judges each bullet against what it does say — the reading found it only by holding the whole sequence against `project.md` at once.

Filed rather than repaired because the remedy is a choice among three, and no instrument settles it: a bullet in stage 8, a clause on stage 1's `Write`, or nothing at all on the ground that `domains/project.md` already binds the seat and the task need not restate it. The third is a live option rather than a null one, since Single Authority on `domains/agent-harness.md` argues against restating a claim that already binds from one surface.

Not established: whether the sibling build tasks have the same shape. This was measured on one document.
