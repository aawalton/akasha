# Claim

`askComposed` is written three times in this repository, and no two of the three are the same function. The one 57 shipped files call fetches a service that is off, so every call arriving there fails. The one 12 files call answers in process off the checkouts on this machine, and works. The third is pure, answers nothing, and is called by nothing. Three implementations of one pages system function is the state `domain/pages-system`'s second intent forbids, but none of the three can go yet: the clean one's query states four fields where the fetching one's states eleven, so it cannot yet answer what the old one answers, and the old one is therefore still the only record of what the new must do.

# Evidence

Read on 2026-08-28 against `5904821c5` on `main`, and run where running was possible. Every count below states the pattern it was taken with, because three of them are counts of different things that a reader would otherwise take for one.

**One, it fetches a service that is off.** `shared/pages-query/src/ask.ts:80` exports `askComposed`, which `POST`s to `${pageQueryOrigin()}/q`. Sixty files import that symbol from the subpath `@shared/pages-query/ask`; three are tests and 57 are shipped. They stand in `alanwalton/web` 14, `shared/pages-access` 10, `tools/lib` 8, `collections/exercises` 4, `temper/web` 3, `shared/person-access` 3, `collections/music` 3, `alanwalton/health-samples-access` 3, `collections/litrpg` 2, and one each in `tools/commands`, `temper/scripts`, `smilingjenny/web`, `shared/person-authority`, `shared/open-questions`, `infra/cluster-checks`, `alanwalton/sms-access`, `alanwalton/mobile-cli`, `alanwalton/location-traces-access` and `alanwalton/health-samples-day`. `pageQueryOrigin()` at `shared/pages-query/src/index.ts:42-48` falls through to the constant at `:7-8`, and nothing answers there: `services/surplus-fall-notifier.ts` logged `went unasked: http://page-query-service.page-query-service.svc.cluster.local:8787/page/page-query/surplus-hours-on-day gave no answer within 5000ms` while this was being read.

**Two, it answers in process.** `tools/lib/page-query-client.ts:90` exports a second `askComposed` with the same name and a compatible shape, which answers through `askedFrom(roots(), ...)` off local files and never reaches the network. Twelve files call it, none of them tests: `services/daily-tracking-points.ts`, `services/great-courses-sync.ts`, `tools/commands/food/log.ts`, `tools/lib/inbox-tracking/{persist,poll}.ts`, `tools/lib/pipeline-run/write-changed-files.ts`, `tools/lib/push-notification/{feed,store}.ts`, `tools/lib/tracking/{held-row,pages,relationships,resolve,sessions}.ts` and `tools/lib/wandering-inn/{filing,run-record}.ts`. `pages/initiative/astra-pages-system-service.initiative.md:24` names this an interim with a stated end.

**Three, it answers nothing, because nothing asks.** `pages-system/query/query.ts:218,277` exports `checkQuery` and `runQuery` over the `Query` at `:74`. It is pure and does no I/O. No file outside `pages-system/` imports anything under `pages-system/query/`; the only mention of it elsewhere is a comment at `editor-extension/src/features/page-tree/harness.ts:61` saying so.

**That zero is the subdirectory's and not the package's, and the difference is where this claim could go wrong.** `pages-system/query/` has no importer. The package `pages-system/` has twelve, counted with `from "[^"]*pages-system/` over `*.ts` and `*.tsx` outside `pages-system/` and outside tests: `page/index/relation/relation.ts`, `page/page-types.ts`, `page/page-type/unsplittable.ts`, `page/property/registry.ts`, `page/required-reading/required-reading.ts`, `tools/audits/domain-edges.ts`, `tools/commands/page/suffix.ts`, `tools/lib/champions-asked.ts`, `tools/lib/champions-roster.ts`, `tools/lib/domain.ts`, `tools/lib/seat-page.ts` and `tools/lib/seat-vocabulary.ts`. Every one imports `pageTypeOf` from `pages-system/page-type/page-type.ts` and nothing else. A sixteen-file count taken with the looser pattern `pages-system/` catches four files that name the package in prose or in a tsconfig rather than importing from it.

**What the clean one would have to grow before the fetching one can go.** `ComposedQuery` at `shared/pages-query/src/ask.ts:33-44` states `page-type`, `where`, `count-by`, `keys`, `sort-by`, `descending`, `limit`, `offset`, `function` and `target`, with `where` an object of per-key predicates. `Query` at `pages-system/query/query.ts:74-89` states `pageType`, `expands`, `keys` and `where`, with `where` a formula string. So the clean one is missing ordering (`sort-by`, `descending`), paging (`limit`, `offset`), grouping (`count-by`) and aggregation (`function`, `target`), and its `where` is a second language rather than the same one narrower. That list is what has to be built, and it stands written down nowhere else.

**`PAGE_QUERY_ORIGIN` is referenced by 26 files and set by none of them that a deployment reads.** The narrow claim is the useful one, because it names where a reader would look to change it: no YAML anywhere in the repository sets it, nothing under `deploy-system/` or `infra/` sets it, and it is absent from both the `env:` block and the `alanwalton-secrets` key list of `alanwalton/web/generated/web-deployment.generated.yaml`, whose env names are `NODE_ENV`, `HOST`, `PORT`, `PAGE_WRITER`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_COOKIE_DOMAIN`, `SUPABASE_JWT_SECRET`, four `SEAWEEDFS_` keys, `GIT_ACCESS_TOKEN` and `HOME`. The broader phrasing "set nowhere" is false and would send a reader looking in the wrong place.

Not measured: whether the 57 shipped callers need a service at all, which turns on whether the deployed image ships `pages/` and could answer from files in process; how many of the 57 are reached in practice rather than merely compiled; and whether `Query`'s formula `where` can express every predicate `ComposedQuery`'s object `where` currently carries.
