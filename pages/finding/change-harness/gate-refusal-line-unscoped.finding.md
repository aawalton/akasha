# Claim

The Design line "Anything a gate could refuse is not written as an instruction" states no scope, and the two available scopes ask for different things. Read across the corpus it is false: "Recorded Reading" on `domains/repos/instructions-repo.md` states exactly what a gate refuses, and its own warrant says why — the gate refuses at the write, with the draft already made. Read as scoped to this tree it is true, but reaches only seats booting here.

# Evidence

Read off the `review-instructions` reading of `domains/change-harness.md` finished 2026-08-21, read line by line, bottom to top. That reading ran `ops instructions run-gates --file-path domains/land.md` and got `[read-before-write] fail — never read by this agent`, which is the gate whose refusal "Recorded Reading" duplicates on purpose.

The reading left the line standing, Design being a section "Every Changed Line" holds for Alan. Either the scope gets named or the exception does.

Not measured here: I did not run the gate myself, did not open `instructions-repo.md`, and did not search for other instructions stating what a gate already refuses — so how many exceptions there are, beyond the one, is uncounted.
