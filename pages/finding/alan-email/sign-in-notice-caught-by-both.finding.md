# Claim

After The Fact and Already Settled on `domains/alan-email.md` ask for different things on one class of mail: "Archive every new sign-in and new-device notice" catches a sign-in Alan did not make, and so does "Anything that can still go wrong is not settled". The code rule `email/alan/rules/code/new-device-notices.md` follows the rule and archives it. Nothing written down says a rule beats a principle on a class it names.

# Evidence

Raised by the seat that read `domains/alan-email.md` on 2026-08-13 under `review-instructions`, and relayed here rather than re-derived: I did not open the two entries or the code rule.

That seat reports reading all thirty-seven rules in the order at `email/alan/rules.md`, the eleven code rules the document's principles and rules claim, and the `email-rule` and `email-action` domains, which is where the override it could not find would have stood.

It offers the override as the likely intent rather than as a defect. Nothing here measures how much mail falls in the overlap, or whether Alan has seen the archived notices and minded.
