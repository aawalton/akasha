# Claim

The cut's README files native OS window management under "Known-absent against the vision", which Alan's 2026-08-04 ruling retired — so it now asserts an open debt against the vision that nobody holds.

# Evidence

`README.md` in `/var/home/walton/code-editor` carries, under a heading naming what the cut still owes the vision: "Native OS window management is absent. This is a served workbench rendered in Alan's own browser, so his named 'window management' degrades to workbench layout plus pop-out browser windows. A consequence of the seed."

That was true when #17543 wrote it. `rulings/window-management-is-the-browser.md` settles it: the browser, installed as a Brave app, IS the answer to window management rather than a shortfall standing in for one, and no Electron shell is to be built or maintained.

A retired debt left in a known-absent list reads exactly like a live one. The specific hazard is that the list is where a later lead looks for the next row, and this entry invites cutting one for work Alan has ruled out — the entry is more expensive than the paragraph it occupies, because acting on it costs a row.

Not corrected in the same breath deliberately. #17747 is parked at `awaiting_alan_verification` against HEAD `480a341`, and its open criterion is that Alan reaches the editor after a reboot. Committing to that repository now would move HEAD, so what he verifies would not be what was verified for him. The correction rides with the next row into this tree.

The whole of the fix is replacing that entry with a pointer to the ruling. What remains genuinely open, and should survive the edit, is the separate question the ruling explicitly does not settle: whether the workbench's own layout and panel arrangement satisfy what the vision asks of window management.
