# Claim

Three `category-rule-*` refusals open by naming the document's path, and the order they cite names rules only by slug — 49 entries, none containing a `/` or a `.md`. So the first sentence identifies the rule by the one token the order never carries, and the sentence it states is true of every live rule rather than only of the refused one. Nothing goes wrong downstream, the remedy line supplying the slug before an author can act, and no instrument sees it.

# Evidence

Raised by the reviewer seat `claude-refusal-archivist-flex-2-review-instructions`, reading `refusals/category-rule-unlisted.md` line by line on 2026-08-14. Its report is at `~/agents/claude-refusal-archivist-flex-2-review-instructions/review-category-rule-unlisted.md`.

That seat measured the order itself — 49 entries, zero containing a path separator or extension — and names `category-rule-orphaned` and `category-rule-shadowed` as carrying the same shape. I did not re-measure it.

It gave three reasons for not landing a repair: the pattern is the family's rather than this document's, so repairing one puts it out of step and repairing all is a horizontal change; a sibling was read and stamped hours earlier by another seat in the same pass, whose reading judged that line keep-whole after explicitly checking it for a second reading, and landing across the family would overturn a call on a line it was not asked to read; and there is a real case on each side.

The fork it states: whether a refusal's first sentence should name the document the author is holding, or the token the order actually carries. Naming the path does tell them which file they are being refused over.

Not measured: whether any refusal family outside `category-rule-*` identifies its subject by a token its cited authority does not carry.
