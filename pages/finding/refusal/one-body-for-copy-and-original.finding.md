# Claim

One refusal body serves both a missing copy and a missing original. `tools/checks/statusline-constants.ts` stops at the first of five files it cannot open, so an unreadable `tools/lib/attributes.ts` reads the same as an unreadable `block-headless-halt.sh` — though only the first means the store's own declarations are unreachable.

# Evidence

Found by the dispatched `review-instructions` seat reading `refusals/statusline-side-unreadable.md` on 2026-08-12, which rendered the body once for each of the four files the check can fail on.

Its rewrite narrows the harm by naming both originals in the body, so a reader can see which side their path sits on. Closing it properly means two refusals, or a hole carrying which side failed — spending a second document on a distinction that only matters while a file is missing.

Not measured: which of the five files actually goes missing in practice.
