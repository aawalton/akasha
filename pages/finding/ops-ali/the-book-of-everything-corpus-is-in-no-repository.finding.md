# Claim

The Book of Everything corpus is in no repository this estate holds. Every `ali` command reads a tree of `profile.md` files under `book-of-everything/`, and that tree is neither in akasha nor in the retired `books` repository it was assumed to have come from.

The supporting code stays by Alan's ruling. `booksRoot()` refuses rather than answering a root the corpus is not under, so a reading over it says it found no corpus instead of reporting zero.

# Evidence

Measured 2026-08-28. akasha holds no `book-of-everything/` directory, and `git log -- book-of-everything` matches 0 commits against 1 for `dirty/book-of-everything`. No `profile.md` exists anywhere under `/var/home/walton/repos`.

The retired `books` bare repo was read directly in the transport pod: 1,215 commits, 2,644 files at `main`, 43.4 MB, last commit 2026-08-26. Its whole top level is `pages/`, `all-about-alan/` and `dirty/`. Of its 2,644 files, 2,633 are page-shaped and the remaining 11 are under `dirty/` and `all-about-alan/`. Every one of those 11 already exists in akasha at the same path, and all 2,589 distinct page basenames are in akasha too. So the pages were absorbed and the corpus was never in that repository either.

The only trace on disk is `dirty/book-of-everything/`, holding `CAPTURE-LOG.md`, `DASHBOARD.md` and `ROTATION.md`; `DASHBOARD.md` opens `Generated by ops ali fold. Do not edit by hand.`, so it is stale output rather than the tree.

Repointing `booksRoot()` at the akasha root made this worse before it made it better: `ops ali pending` exited 0 reporting `0 points not yet landed` over an empty population, because its scan prefix `book-of-everything/` matches no commit. That traded a loud refusal for a silent zero. It now exits 3 naming the missing corpus.
