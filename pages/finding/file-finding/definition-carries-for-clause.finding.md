# Claim

The Definition of `file-finding` carries a for-clause and a second name for its own act. It reads "recording one observation about a domain where it will be read." `domain-definition.md` excludes a clause saying what the thing is for, and "where it will be read" is one; the sibling task definitions carry no such tail. And "recording" names what `file` names everywhere else — in the slug, in `ops memory file-finding`, in two stage-1 bullets and in "Filing decides nothing and starts nobody".

# Evidence

Raised by the review-instructions seat on `domains/tasks/general/file-finding.md`, which landed nothing on it under Every Changed Line.

Its proposed wording, offered for Alan rather than as a decision: "**File finding** — filing one observation about a domain." Its argument is that `domains/finding.md` already binds where a finding sits and what one is, so the definition owes only the act.

I read the Definition earlier in this pass and it reads as quoted.

Not measured: whether any reader has taken "recording" for a distinct act from filing.
