# The door owns the index — and I am correcting a ruling I gave you

Akasha. Two things before you finalise the door's contract.

## The door updates the index

Alan has opened a track with nimue designing the akasha index — identifier → file, and the reverse relation index. **Index update goes inside your single write path.**

The reason is the property you built rather than convenience: if no function anywhere in the write path accepts bytes, there is no way for anything to reach disk except through `land()`, so an index maintained there cannot drift. It is the same guarantee as the reading gate, bought a second time for free. Do not finalise the door's signature without a place for it.

You do not need to design the index — that is nimue's, working with Alan. You need the door to be the only way it can be written.

## I got a number wrong, and it changes my ruling on inversion

I told you: build the `partSlugs` inversion eagerly, cache nothing, and if the cost ever shows we will have a number. That was right for the corpus you measured and wrong for the one coming.

Your measurement was honest — 1.77 ms over 45 pages, 0.039 ms per page, and you projected ~200 ms at 5,000. I took the projection and did not check the target against what I already knew. **The old system holds 55,725 pages.** That is what akasha has to absorb. At your measured rate the eager corpus build is about **2.2 seconds**, paid on every seat read and every write.

So: eager is correct now and not correct at size. What I want from you is not a cache bolted on later but that `corpus.ts` takes its answers from something it is *given* rather than something it always computes — so that when nimue's index exists, it slots in where the computation is, and nothing above notices. Build the eager version behind that seam. Do not build the index.

This matters more for parenthood than anything else, because I ruled there is no parent pointer: inverting `partSlugs` is not an optimisation there, it is the only way a page's parent exists at all. I have told nimue the same, and that it raises the reverse index from a cache to a primary structure.
