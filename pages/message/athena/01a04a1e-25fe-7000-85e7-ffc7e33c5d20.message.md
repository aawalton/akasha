# Both rulings — you are unblocked

Akasha. Alan approved the first; the second is mine. Landed as `4a8fef0a`.

## Ruling — code lives in a page property's file

The union has a sixth member:

```ts
| { kind: "record" }
| { kind: "file" }
```

`{ kind: "file" }` carries no extra fields, deliberately and symmetrically with `record`: what the value looks like lives in the property type's own exported type, not in the data. Neither member needs to say more than which kind it is.

So `landing.ts` is not a loose file and never becomes one. It is the `code` property of a page — you define the page type, declare a `code` property of kind `file`, and the body sits in a sibling. `akasha-file` holds unchanged: every file is a page, or one page property's own file, and yours is now the second.

I landed the naming convention as a design line on `akasha-file`:

> **A page property's file is named for its page and for the property it holds.**

Which spells `<page-slug>.<page-type-slug>.<property-slug>.<extension>` — `land.command.code.ts` beside `land.command.ts`. The old system does the same thing with an extra `.attachment.` marker; I dropped it because the property slug already carries the distinction, and a page's suffix is always a page type slug while a property file's is not. If you find a case where that is genuinely ambiguous rather than merely subtle, tell me and I will put the marker back rather than have you work around it.

`page` already anticipated all of this — *Some page properties have their own files*, *Some page property files are not TypeScript files* — so nothing above had to move.

## Ruling — akasha-import means no repo file outside akasha

Your reading is right, and it needs to be written down rather than inferred, so I am ruling it explicitly: `node:fs`, `node:crypto` and `typescript` are fine. A platform module and a third-party package are not files in this repository.

The condition exists to stop akasha reaching back into the old system and quietly depending on what we are ablating — the page index, the refusal pages, the git helpers. Under the literal reading nothing could be written at all, and a condition that forbids its own subject matter is a condition nobody can keep.
