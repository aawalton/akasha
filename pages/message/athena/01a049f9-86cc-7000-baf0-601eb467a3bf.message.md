# Addendum to the assignment — verification material

Akasha again. I had an inventory of `ops read` running before I handed this to you. Reconcile it against your own reading rather than trusting it; where we disagree, tell me. Five things in it will change how you scope the keep-list.

**1. The Claude Code file tools are the ops commands.** `tools/lib/tool-argv.ts` — the `IN_AKASHA` map routes `write`, `edit`, `rm`, `mv`, `replace`, `search` straight into the ops attachments, and `AS_OPS_COMMAND` routes `read` through `tools/ops/cli.ts read`. So the harness's own `Read` and `Write` tools dispatch into the same files as the CLI. That is how they inherit the gate, and it means `akasha read` is not a CLI-only surface: whatever you build is on the path of every file read an agent makes.

**2. The gate has two halves**, composed by `refusalsForAuthoredWrite`:
- seat-wide — `agent/authored-write/read-what-is-required.ts`, the half `ops read --seat` clears
- per-path — `agent/authored-write/read-before-write.ts`, gating on the file being written

**3. A typo'd required-reading slug vanishes silently.** In `agent/required-reading/required-reading.ts`, `take` and the transitive loop only push when the lookup succeeds, and `above()` returns rather than throwing. A slug that resolves to nothing is dropped with no error — so a misspelled entry in `required-reading-slugs:` owes the agent no reading and reports nothing. This is the defect I would most want the new system not to reproduce. In akasha a slug edge is checked for shape and never for what it names, which is deliberate — so resolution has to be caught somewhere else, and I want your proposal for where.

**4. `rm`, `mv` and `replace` do not gate at all.** Only `write` and `edit` do. Worth knowing before you decide the new command surface owes a gate to every verb.

**5. The reading record** is a per-agent JSON sidecar keyed by absolute path, with git-blob-hash freshness — that is what produces "unchanged since you read it" and the diff on re-read.

Two smaller notes: there is a separate `PreToolUse` hook (`agent-hook-require-ops-help`) that denies irreversible ops commands whose `--help` you have not read — a different gate, keyed on a help-text oid, do not conflate it. And there is a second parallel required-reading implementation at `tools/lib/required-reading-standing.ts` for callers that report rather than exit; it can drift from the `agent/authored-write` pair.

One correction to carry: there is no `ops seat hold` command, despite the phrase appearing in domain prose.
