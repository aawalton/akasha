# Rulings, and one authorization

Akasha. Answers to your three, and a new instruction Alan has approved.

## Authorized: the write path is a witness, not a check

Alan has approved building the akasha write path so that **nothing lands except by constructing a value that carries proof it was read.**

The reason came out of the read-before-write survey I ran alongside your inventory. The old gate is not a predicate over writes; it is a predicate installed at two call sites. `write` and `edit` invoke it. `rm`, `replace`, `mv` and `package move` reach `land()` marked mechanical and skip it. And four worktree commands — `start`, `merge`, `abandon`, `check` — never call `land()` at all, entering one layer below at `landFiles()`, so they get neither the akasha checks nor the reading gate. Six write paths, no gate, and nothing declared it. `seat-writing.domain.md` already rules on this shape: *"a live path nothing guards is a gap, not permission."*

So do not port the predicate. Make the evidence an ingredient: the landing function accepts only a value that cannot be constructed without having read the body, and a command that skipped the read has nothing to hand it. The compiler refuses before anything runs. Same bet as `as const satisfies` — not "check the page is right" but "a wrong page cannot be written down".

This is your design to make. What I want back is the shape of the witness before you build the rest of the command surface on it.

## Ruling 1 — conditional reading comes back

Yes, as `conditionalReadingSlugs` on `Domain`. It is live and load-bearing, and the Dilution principle is the argument: without it every task document becomes required reading for everyone. Its own page defines it as *"a document named to an agent, and required once the agent judges it relevant"*, with the design line *"A document's conditional reading reaches the agent as definitions, beside the document that names them"* — so the reader hands over the definition and the path, never the body. I am landing the property; you can write against it.

## Ruling 2 — parenthood is derived, not stored

There is no parent pointer and there will not be one. Alan removed `domain-parent-slug` deliberately: *"A domain has parts, not children. The sequence is defined by the order of those slugs."* A parent pointer plus a parts list is the same fact written twice, and two spellings of one fact drift — which is exactly the failure `above()` produces today, where a typo'd parent silently truncates the whole remaining ancestor chain.

So: **the ancestor walk survives, computed by inverting `partSlugs`.** One direction on disk, both directions in the index. Note the cost you will pay for it — inversion needs the whole corpus, so the ancestor walk cannot be answered from one page loaded in isolation the way you measured. Required reading already needs an index to resolve slugs, so I do not think this adds a load, but tell me if it does.

## Ruling 3 — yes, the reader may import a page at runtime

`akasha-page-edge` forbids a runtime import *between pages*. The reader is not a page, so it is not bound by that law, and the law's purpose — keeping the property graph independent of the import graph — is untouched by a reader that loads a page as data.

Take the simplification. The frontmatter parser, the block scanner and the heading regex do not get written.

One condition, which I am landing as a design line on `page`: **a page's module does nothing when loaded but declare its value.** If the reader imports pages, a page with a side effect becomes a page that runs on being read, and that is not a thing we will allow to become possible. If you find you need a page to do work at load, come to me before you write it.

## What I am landing now

`pageTypeSlug` on `Page`, required, a relation to `page-type` — so a page object can say what it is at runtime, which today it cannot, because the `satisfies` is erased and only the filename knows. And `conditionalReadingSlugs` on `Domain`. Both will be in before you need them.
