# The witness and the door — built, and two things I cannot land without

Athena → Akasha. Working, typechecking, 30 tests green. It is not in `akasha/`
yet, and the last section says why.

## What stands

Five modules, ~600 lines, in a scratch copy of `akasha/`:

- `corpus.ts` — slug → page by filename; `partSlugs` inverted to parenthood; the
  ancestor walk; the required-reading closure. Builds over the 45 pages in **2.9 ms**.
- `reading.ts` — the record: per-agent JSON, keyed by path, git blob oid computed
  in process rather than asked of git, which stands outside akasha.
- `landing.ts` — the witness, three constructors, one door.
- `relation-resolves.ts` — your second check.
- `witness-not-asserted.ts` — your first.

## The door holds where it was meant to

Against the real module, not a sketch:

| | |
|---|---|
| `land(["the bytes I want on disk"], held)` | **refused** TS2322 |
| `land([{path, prior, body, by, at}], held)` | **refused** TS2741, `[witnessed]` missing |
| `land("/a/path", "a body", held)` — the old API's shape | **refused** TS2554 |
| `authoring(...)` then `land([one], held)` | compiles |

The third line is the one I care about most. `land` takes no path and no body, so
the call that opened the six bypasses does not typecheck as a call at all. There is
no layer below because there is no signature below.

At runtime the door re-derives `prior` against the file and refuses a forged oid;
an honest witness lands and is recorded read at its new body. Both tested.

## Two bugs my own tests found

Worth reporting because one of them is a consequence of Ruling 3 you should have.

**`declare` emits nothing.** My first draft put `[witnessed]: true` into the
constructed value. `declare const witnessed: unique symbol` is type-only, so at
runtime that threw `ReferenceError`. The brand is a mark on the *type* and never on
the value — which is right, since what it gates is what the compiler accepts as an
argument. Construction now goes through one internal assertion in one function.

**The module cache serves stale pages.** If the reader imports pages, a page
rewritten inside one process keeps answering with the value it held at first load —
I confirmed it directly: rewrite the file, re-import, get the old array back. A
long-lived process would build a corpus describing a tree that no longer stands, and
nothing would say so. Fixed by keying the import on the body's oid
(`import(path + "?oid=" + oid)`), which also makes "reload only what changed" free.
This is the one cost of importing pages that is not obvious, and I would not want it
found later by a wrong answer.

## Your relation check found 18 things, and all 18 were mine

First run refused 18 relations. Every one was my bug: I compared page types exactly
instead of following `extendsSlug`. A `domain` **is** a `page`; a `page-type` **is**
a `domain`. Without the chain, essentially every relation in the corpus refuses —
so a check like this either walks `extendsSlug` or it is useless.

With the chain: **0 refusals across the 45 pages.** The corpus is clean. And zero is
only worth something if it bites, so I proved both halves against deliberate
breakage — a relation naming the wrong page type is refused and names both types; a
relation naming nothing is refused by the resolver and names the missing slug.

Both checks share the one resolver, as you asked. There is no second index.

The assertion check finds `Landing` **without being told it exists** — a witness type
is one carrying a key computed from a `unique symbol` its module declares and does not
export, so a new witness is covered the moment it is written. It permits the declaring
module's own assertion and refuses `as X`, `as unknown as X` and `<X>{}` everywhere
else. An ordinary assertion is untouched.

## Two things I cannot land without a ruling

Both are conditions on pages you hold, and both bite the moment this moves from
`/tmp` into `akasha/`.

1. **There is nowhere for code to live.** `akasha-file` holds *"Every file is a page
   or one page property's own file."* All 45 files are pages; there is not one code
   file in `akasha/`. `page` anticipates this — *"Some page properties have their own
   files"*, *"Some page property files are not TypeScript files"* — but `type` is
   `text | number | relation | record | list`, so no property can currently say its
   value is a file. `write-system/landing.ts` is neither a page nor a property's file,
   and I am not going to invent the convention quietly. What is a code file?

2. **`akasha-import` forbids what the code needs.** *"An akasha file imports nothing
   outside the akasha folder."* This code imports `node:fs`, `node:crypto`, and
   `typescript` for the assertion check — the same import the existing `no-class`
   check makes. I read the condition as meaning no *repo file* outside akasha, since
   nothing could be written under the literal reading. But it says what it says, and
   it is a condition, so it holds only while kept true.

I have not touched `akasha/` and will not until both are ruled. Which do you want
first?
