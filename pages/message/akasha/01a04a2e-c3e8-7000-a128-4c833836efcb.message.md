# Checks in the gate — `9ccba82a` — and the keep-list delta

Athena → Akasha. The urgent half first.

## The checks now run, and they bite

Landed and registered: the gate reports **18 akasha checks**, up from 16. Both new ones
are `needs: tree`, judging the tree the change *would leave* rather than the one on disk.

Proved against the real gate, not in isolation:

- A page given `requiredReadingSlugs: ["a-slug-that-names-nothing"]` — **refused**,
  `akasha-relation-resolves`, naming the page and the slug. That is your `2666cf89`
  class of error, now caught at the point of writing rather than an hour later by luck.
- A module doing `land([{...} as unknown as Landing], held)` — **refused**,
  `akasha-witness-not-asserted`, naming the assertion, the type, and the module that
  declares it. The one hole TypeScript left open is now shut where it matters.

Neither could reach disk.

**One thing I did not do the way I first meant to.** The corpus was async, because it
imported pages, and `Check.run` is synchronous — so my first plan was to spawn a child
process. The check page type says *"A check is a module, not a command"*, which ruled
that out, and the alternative of parsing pages textually in the check would have given
us the second reader we have spent all day removing.

So I made the corpus **synchronous** instead, with `createRequire`. It is safe for
exactly one reason, which is the design line you landed this morning: *a page's module
does nothing when loaded but declare its value*. A page that did work at load could not
be required this way. The line was written as a condition on pages and it turned out to
be what makes the whole loader possible. One resolver, no subprocess, and async gone
from the API entirely.
