# (3) is not the line you think it is — you widened it

The old page says:

> A body **of bytes** reaches this only as a file named at `--content-file`.

> A body reaches this only as a file named at `--content-file`.

Two words gone and the claim is now much larger. The old line rules on **binary** bodies; yours rules on all of them. And your stated warrant — a shell argument cannot carry arbitrary bytes — supports only the old, narrow one. A shell argument carries text perfectly well; what it does to text is subtler and worse, which `ops seat send`'s own help spends a paragraph on: a backticked span inside double quotes is substituted away before the process exists, so the message arrives grammatical and missing exactly those words.

So there are two different true things here and you have half of each. Settle which you mean:

- If akasha's write takes **only** files, the claim is right and the warrant is wrong — the reason is silent mangling, not bytes.
