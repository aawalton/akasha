# `akasha read` — the keep-list

Athena → Akasha. Inventory of `ops read`, then keep/drop/defer per feature.

## What changes the scope

Three findings move this more than any individual ruling.

**The harness Read tool *is* `ops read`.** `tools/lib/tool-argv.ts` routes `read.ts`
through `tools/ops/cli.ts read`. So every feature kept is paid on every file read
an agent makes in any repo — not only on akasha pages. That is the argument for a
short list, and it is why I drop three warrant kinds that each cost a filesystem
walk or an index lookup on every read and have never once fired.

**A page is executable, so the reader imports it instead of parsing it.** Measured:
`Object.keys(akashaSystem)` gives the exact property list; `.requiredReadingSlugs`
gives the exact slugs as data. Every edge is `import type`, so it erases — bundling
one page yields 36 lines and **zero** imports, loading in 0.4 ms. A page loads in
isolation with no transitive cost. This *deletes* rather than ports: the frontmatter
parser, the document block scanner, the `^# (.+)$` heading regex behind section
warrants, and the parse-and-memoize half of the address index. "Malformed
frontmatter" stops being a category of error.

**`akasha` cannot import outside `akasha`** (`akasha-import.domain.ts`). git, the
page index, the refusal pages and the repo roots are all outside. Nothing is
inherited — every keep is a rebuild. I have priced each one accordingly.

## What the compiler actually carries — measured, not assumed

Real tsc against a copy of `akasha/`, breaking pages one at a time.
(My first run was worthless: `npx tsc` pulls a deprecated shim that exits 0 on
everything. Worth knowing before anyone wires it into a check.)

| Malformation | Compiles? |
|---|---|
| missing required property (`definition`, `id`) | **bites** TS1360 |
| unknown / excess property | **bites** TS2353 |
| three aids where the type says exactly two | **bites** TS2322 |
| `definition` of 150 chars where `max` is 100 | passes |
| `requiredReadingSlugs` naming a slug that exists nowhere | passes |
| `id` that is not a uuid | passes |
| `slug` duplicating another page's slug | passes |

The residual check surface is exactly four: **max lengths, slug resolution, uuid
format, slug uniqueness.** Everything else the compiler already does, and
`akasha-check` forbids a check that tests what the compiler tests. The 15 ops
checks do not port; four rules do.

## Correction to the brief — the typo'd slug

Your point 3 is real but narrower than stated, and the repo already contains the fix.
There are **two** required-reading implementations and they disagree:

- **File warrants** — `page/required-reading/required-reading.ts:57-64`. `pointing()`
  **throws**: *"a reading named and never reached is one the agent is never handed,
  so it is refused here rather than dropped."*
- **Seat warrants** — `agent/required-reading/required-reading.ts`. `take()` :104 and
  the closure loop :132 push only on a successful lookup; `above()` :64 returns.
  All three drop silently.

`above()` is the worst of them: a typo'd `domain-parent-slug` does not drop one
document, it truncates the **entire remaining ancestor chain**, silently shrinking
everything downstream of it.

So we do not need a new idea. One half of the old system decided this correctly and
wrote the argument into its own error message. **`akasha read` resolves like
`pointing()`, not like `take()`.** It costs nothing — the reader already resolves
every slug it prints — and it respects `akasha-page-edge` ("a slug edge is checked
for its shape and never for what it names"), because refusing at resolution is not a
check on an edge; it is the resolver declining to report a closure it knows is short.

## DROP

| Feature | Why |
|---|---|
| Extension warrant (`index.pageNamed("extension", ext)`) | Inert — no page on disk declares `extension:`. A lookup on every read that has never fired. |
| Package warrant | Walks up for the nearest `package.json` on every read. There is no `package.json` inside `akasha`. |
| Repo warrant | akasha is one folder in one repo; a constant, not a per-file warrant. |
| Heading warrants via `^# (.+)$` regex | Replaced exactly by `Object.keys(page)` → the property's page-property-type. Inferred becomes exact. |
| Ending/glob warrant for page type (`files:`, `.domain.ts`) | The page type is the `satisfies` import. Exact, and already load-bearing for the compiler. |
| `sequence-slugs`, `expands`, `body-shape-slug` | Already dead in the closure. `partSlugs` replaces `sequence-slugs`; the body is gone, so body-shape has no referent. |
| `git diff --no-index` as the diff engine | Two temp files, a subprocess, and it needs the prior body to have reached a commit — hence three fallbacks to whole-file. git is outside akasha. Keep the intent, not this. |
| Generated-file sniffing (6 heuristics, incl. regex over first 3 lines) | In akasha every file is a page or one page property's file. Generated is structural, not sniffable. |
| `--repo` special-case error | One folder. |
| `seatDefaults()` compiled off page-type `default:` | A second place a seat's attributes can come from. One spelling. |
| `mechanicalOid` | Exists for `mv`/`replace` rewriting bodies. Those verbs do not exist here yet — do not add for a case not present. |
| Conditional slugs hardcoded to resolve as `task` | Gratuitous coupling; resolve by slug like everything else. |
| The second parallel closure at `tools/lib/required-reading-standing.ts` | Two implementations that can drift. One. |
| `--seat` skipping the file closure entirely | An asymmetry, not a feature: a seat read prints no page-type chain, a path read prints no seat warrants, and a write demands both. One closure, both modes. |

## DEFER

| Feature | Until |
|---|---|
| Conditional reading | It has **no home in the new `Domain` type** — see ruling 1 |
| File-relation warrants (`command-path`, `script`, `widget-path`) | Code and page are one file here, so the relation is degenerate. Revisit if attachments return |
| Lockfile around the record flush | The sidecar is per-agent; wait for two of an agent's processes to actually collide |
| Refusal texts as pages | They live outside `akasha`. Inline them now, page them when the page system is inside |
| `ops read` also running `akasha read` | Not a shim over working machinery — see below |

## On Alan's item 4

`ops read` cannot currently expand the new pages at all: reading
`akasha-system.domain.ts` pulled **none** of its eight named slugs, only the repo
page. The old reader cannot see the new format. So "`ops read` also runs
`akasha read`" is not a small piece of plumbing over something that works — the
closure has to exist first, or the double-run exercises nothing. I would build the
closure and the record, prove them on the 38 pages that exist, and wire the
double-run after.

## Loose ends found on the way, not part of the ruling

- `no-method-signature` is a fully written check with a test and **no `.check.md` page**,
  so the registry never sees it. Two check directories are empty.
- Irreversibility is spelled twice and only the code gates: 39 documents say it,
  5 code sites say it, they overlap on 3. `ops rm` and `ops deploy` are irreversible

- `ops package move` is registered twice and permanently shadowed — dead code.
- 332 commands across 3 registries. The lesson I take for `command-system`: one
  registry, one spelling of a fact, one implementation.

## Rulings I need

1. **Conditional reading has no property on the new `Domain` type.** It is live —
   my own seat read printed 11 of them. I want to keep it: without it every task
   document becomes required reading, which the Dilution principle forbids, or
   tasks become undiscoverable. Does it come back as `conditionalReadingSlugs`?

2. **There is no parent pointer in the new system.** `domain-parent-slug` drove the
   ancestor walk; the new type has only `partSlugs`, pointing down. But
   `domain.page-type.ts` still carries "Everything a domain carries could matter to
   every domain beneath it." Is parenthood derived by inverting `partSlugs`, or is
   required reading now purely explicit? This decides whether the walk survives.

3. **May the reader import a page at runtime?** `akasha-page-edge` forbids a runtime
   import *between pages*. The reader is not a page. If it may, the frontmatter
   parser and half the index never get written. This is the largest single
   simplification available and I think it is the one for Alan.
