# The shape of the witness

Athena → Akasha. The design, and the one place it does not hold.

## Definition

- **Witness** — proof, carried as a value, that an author read what they are overwriting.

## What it must fix

The bug is not that the old gate was wrong. The gate is correct where it runs.
The bug is that it is a **predicate installed at call sites**, and six write paths
do not call it: `rm`, `replace`, `mv`, `package move` reach `land()` marked
mechanical; `worktree start|merge|abandon|check` enter at `landFiles()` one layer
below and get neither the checks nor the gate.

Both shapes have one cause: **there is a function in the write path that accepts
bytes.** As long as `landFiles(path, bytes)` exists, "one layer below" exists, and
a new command reaches it by writing the obvious thing. No predicate can close that,
because the predicate is what is being skipped.

So the fix is not a better gate. It is that **no function anywhere in the write path
accepts bytes.** The lowest layer takes `readonly Landing[]` and nothing else. Then
there is no layer below to enter.

## The shape

```ts
declare const witnessed: unique symbol        // declared, never exported

export type Landing = {
  readonly [witnessed]: true
  readonly path: AbsolutePath
  readonly prior: Oid | null                  // null only where the path is new
  readonly body: string
  readonly by: WriterId
  readonly at: EpochMs
}
```

Three constructors, and they are the only exported way to obtain the type:

- `authoring(path, body, writer)` — the ordinary write. Reads the body on disk,
  verifies the seat closure and the path closure are discharged, records `prior`.
- `carrying(from, to, writer)` — a move or a mechanical rewrite. Bytes no author
  chose, so it records the source oid rather than an authored reading. It is
  **still a constructor**: `mechanical` stops being a boolean that turns the gate
  off and becomes a kind of witness you must actually produce.
- `creating(path, body, writer)` — a path that does not exist. `prior` is null;
  the closures are still verified, because a new file owes its reading too.

`removing(path)` returns no `Landing` and needs none. `agent-harness.domain.md`
already rules on this: *"A removal has no author, so no check weighing one runs on
it."* That is a principled absence, not a seventh hole.

## Where it holds, and where it does not — measured

I built it and tried to defeat it. Real tsc, repo settings.

| Attempt | Result |
|---|---|
| `land(["just the bytes"])` — the `landFiles` bypass | **refused** TS2322 |
| `land([{path, prior, body}])` — a plausible object | **refused** TS2741, `[witnessed]` missing |
| `land([{path, prior, body} as Landing])` | **compiles** |
| `land(["nonsense" as unknown as Landing])` | **compiles** |

**So the type stops omission and does not stop assertion.** I want to be exact
about that rather than sell you a guarantee I tested and know to be false.
TypeScript permits `X as T` whenever either type is assignable to the other, and
every opaque type is assignable to the shape you assert from — no brand, private
field or phantom closes it, and `no-class` rules out the one construction that
comes closest.

This is the right trade, because **omission is the entire observed bug**. All six
live bypasses are omissions — commands that never called the predicate. Not one is
a forgery. The type catches every member of the class that has actually occurred.

Against deliberate forgery, two cheap layers finish it:

1. **The door re-derives what it was handed.** `land()` compares `prior` against the
   blob oid on disk now. A forged witness carries a wrong oid and is refused; a
   witness carrying the right oid required reading the file to obtain it. The
   cheapest forgery is doing the read. This also earns its keep honestly — it is
   the check for "someone else changed this since you read it".
2. **One check: no type assertion to a witness type outside the module that
   declares it.** ~40 lines against the TS AST, the same shape as `no-class`. This
   is the only new check the witness needs, and it is exactly the kind
   `akasha-type` sanctions: *"A limit no type can carry is enforced by a check."*

Net: the residual check surface goes from four to five. The 15 ops checks still
do not port.

## Your question: does inverting `partSlugs` add a load?

Yes, a small and bounded one. Measured over the corpus as it stands (45 pages now):

- slug → path by **filename** walk, contents never opened: **0.05 ms**
- **import every page** to invert `partSlugs`: **1.77 ms** total, 0.039 ms per page

Because filenames are `<slug>.<page-type>.ts`, plain slug resolution needs only a
directory walk. Inversion needs the body of every page. So it is a real change of
kind — directory listing becomes whole-corpus load — but the constant is tiny:
about **200 ms at 5000 pages**, and it is paid on seat reads and writes, not on
ordinary file reads. I would build it eagerly and only cache it if the corpus
grows past the point where 200 ms shows.

## What I propose to build first

The witness and the door, against the 45 pages that exist, before any command
surface sits on it. A command written against a door that takes bytes has to be
rewritten when the door changes; one written against `Landing` never does.

## One thing to rule

The witness as drawn discharges **both** obligations at construction — the seat
closure and the path closure — so `Landing` means "this seat owed nothing and read
what it is overwriting". That is one door and one meaning, which I prefer.

The alternative is two types, `SeatCleared` and `PathRead`, composed at the door.
It is more precise about which half failed, and it lets a long-lived process clear
the seat half once instead of per file.

I want the single door. Do you?
