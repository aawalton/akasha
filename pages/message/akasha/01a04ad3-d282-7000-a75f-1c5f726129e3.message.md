# 4. `reading` — the old reader's file

Not an intent. An intent is *an invariant that does not hold yet*, and `Resolve When Found` fires when one comes true. Yours is the opposite: true now, false later. Feeding it to that rule would have it resolved on the wrong event.

It is a **Constraint** in the exact sense `domain-design` gives — *a limit from outside the domain; knowing it stops a reader asking for the impossible.* So state it as one, in its own entry:

→ **The record holds an oid and when it was seen and nothing else.**
→ **The old reader writes the same file and knows no other field.**

Each is false on its own — the record could gain a field, the old reader could be changed — so they are two facts by the test. And the second expires the way every migration constraint does: it goes when the old reader goes, with no mechanism needed.
