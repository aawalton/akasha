# The ask: `runs` does not belong on `akasha-import`

The page's concern is **one file using what another declares** — a static import, one file naming another. That is what the definition names, and a Definition names one concern.

`createRequire(at)` is not one file using what another declares. It is a program loading a file it was handed the path to at runtime, with no declaration anywhere. Your new verb is correct about the system and wrong about this page: **you would be widening a condition past the concern its page is defined by**, and the page would then hold a condition about two mechanisms while its definition names one.

That is the thing I would not let past. It is small and it is exactly how a page stops being about one thing.

Three ways out, and the choice is yours:

1. **Move the condition.** The invariant is about the akasha boundary, not about importing, and it should sit wherever that boundary is owned. `akasha-import` keeps a condition about imports if it needs one.
2. **Widen the definition too**, and accept the page is no longer about imports — in which case it should not be called `akasha-import`.
3. **Two conditions, two pages.** Honest, and probably one page too many for one fact.

I would take the first. The finding is not about imports and never was — Thea's escape route was a runtime load precisely because it is not an import.

# The platform, which I think needs no clause

You are right that an exception clause on a condition is ugly and that reading *the akasha folder* as *this project's code* is a reading the words do not carry. There is a third option: say what actually separates the two.

What distinguishes `node:module`, `bun:test` and `typescript` from `checks-system/check/foo.ts` is not that they are platform. It is that **they are not files of this repository.** And the corpus already has that word — `akasha-repo`'s definition is *the repository nothing tracked is outside*, and its design line is *Nothing under `.claude` is tracked here*.

→ **An akasha file runs no tracked file from outside the akasha folder.**

Run it against the four cases:

- `node:module` — not a tracked file. Allowed, no clause needed.
- `typescript`, `bun:test` — under `node_modules`, untracked. Allowed.
- `checks-system/check/...` — tracked, outside. **Forbidden**, which is the ruling you wanted to keep.
- `checksAt(outside.checks)` resolving to a repo path — tracked, outside. **Forbidden**, which closes Thea's escape.

No exception, true as written, and `tracked` is the repo page's own word rather than one I invented.

**The hole, since I would rather name it than have you find it:** a build artifact outside `akasha/` — an untracked `dist` — would slip through, and it is built from tracked files, so it violates the spirit while satisfying the words. I do not think that is worth a clause either, but you should land the line knowing it is there rather than discover it when someone points a loader at a `dist`.

# The general rule your gap two is an instance of

> A condition that is false on every file in its scope is not being kept, and cannot be.

That is the finding, and there is a test in it that would have caught the line at authorship:

→ **If you cannot write the check without exceptions the line does not state, the line is wrong.**

Nobody could have enforced *imports nothing outside the akasha folder* without excepting `node:*`, `bun:test` and `typescript` — three exceptions the words do not contain. The gap between the line and the check that would enforce it was the whole defect, visible from the first day, and nobody looked because everyone read the intent.

That is the same family as *write the test, not the line*, from the other end: **imagine the check before you land the line, and if it needs exceptions, the line is not what you mean.**

# On the conclusion surviving its reason

This is the part I would keep from tonight, above the wording.

Your ruling held and your reason did not — and the reason is what gets reused. Nobody re-derives a conclusion; they carry the argument to the next case. Someone reading *imports are forbidden, therefore checks live inside* would have met the `checks: string` field, seen no import, and let it through in good faith with three `createRequire` precedents to point at. **The false reason was the escape route.**

→ **When a reason is falsified, re-derive the conclusion rather than keep it.**

You did that. It is why the answer got narrower and better instead of merely surviving.
