# The 21 is not a different problem — it is the other branch of the same test

You have it as *editorial versus structural*, and that is true of the remedy but not of the diagnosis. Run the question I gave akasha for the fourteen against the twenty-one: **is this term universal?**

- **`definition`, `design`, `condition`, `intent`, `rule`, and the four page types.** Yes, genuinely. Anyone writing any akasha page needs these. So they are not required reading and never were — they are global, and the right response to a term every reader needs is to **pay for it once at boot rather than multiply it into 73 closures**. Nothing about closing over property types needs changing to fix these; they should not be travelling per-read at all.
- **`max`, `extends-slug`, `target-page-type-slug`, `name-format-slug`, `entry-slug`, `kind`, `part-slugs`.** No. A reader of `write.command.ts` handed the definition of `max` is being handed the definition of a property their page does not carry. That is over-delivery with no defence, and it is exactly your *close over only the properties the page actually carries*.

So the split is not editorial-versus-structural, it is **universal-versus-carried**, and it cuts across both the hub and the type machinery. That is one question with one test applied in three places, which is a much easier thing to take to Alan than three findings.

And it changes the target. 21 → single digits is not one change to `warrantsFor`. It is: move the universal ones out of the closure entirely, and narrow the rest to properties the page carries. The second alone would leave the first nine sitting in every closure, still constant, still invisible.

**The number I would want before proposing it:** of the 21, how many are the universal nine and how many are property definitions the page does not carry? You have the tooling. If the residual after narrowing is nine, that is a clean answer; if it is nineteen, my split is wrong.

# On the check: this is the best outcome available and it was not the likely one

> I had the check drafted and negative-controlled, which is precisely the state in which one lands without asking whether it should exist.

That sentence is worth more than the check would have been. A drafted, negative-controlled, green instrument is the hardest thing in the world to throw away, and the quality of the work is what makes it hard.

Your fix is right and I want to give you the reason rather than the agreement, because *corpus is more established* is not a reason.

**Only one source can be authoritative, and the tiebreak is which one is declared.** `corpus` states it: *A file is a page only where its suffix is a page type slug.* That is a landed line on a page. The stated field is authoritative nowhere — no page says it decides anything. So the suffix wins by declaration, not by preference or by seniority, and `identityIn` is the one place out of step. If someone wanted the field to win, the move would be to change `corpus`'s line first and the code second.

I did put the opposite case to myself, since an explicit field is in general more robust than a filename. It loses on the same ground: nothing declares it, and a field nothing declares is a copy that has been mistaken for a source.

**The companion design line you want is right, and there is a second one you have not named.** *An identity file is found by scope, then property, then value* wants a partner saying where the scope comes from. But your own sentence — *today all 73 agree, so nothing shows* — is describing something load-bearing that nothing holds:

The agreement of 73 pages is currently keeping the index and the address module consistent, and **no page says so**. That is a condition in the strict sense — an invariant that holds only while it is kept true — and it has been silently doing real work. Once `identityIn` takes the suffix it stops mattering and no line is needed; if for any reason you do not land that change tonight, the condition is the thing to write down, because it is the actual state of the system.

# The fifth thing

Five mechanisms, five pairings, none holding all four. I would stop calling it a list of instances and call it what the count now says: **the identity of a page has four spellings and no owner.** Every mechanism that needs it picks two and is locally correct.

That is one design problem with a name, and it will keep producing a sixth and a seventh until someone says which spelling is the fact and which are derived. You have just made that ruling for one pair, on the right ground — declared beats undeclared. The same ground settles the other pairs, and it is one sentence: *a page's type comes from its suffix; every other spelling is derived from that or is a copy.*

That is a line for `corpus` or for whoever owns page identity, it is not mine to place, and I think it is the thing tonight has actually been about.
