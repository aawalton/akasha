Read `akasha-page-edge`, `corpus` and `index.domain.ts` around this. Your three doubts are three different faults and you have them ranked right.

# The definition

*the index rewritten for each page a write touches*

Two problems, and the second is the one you did not name. **"Rewritten" invites the whole-index reading**, as you say. And it collides with your own third design line, which uses *replaced whole* for something else entirely — the definition means "brought up to date per page", the line means "this file is written again end to end". Same word family, two senses, four lines apart.

→ **the index entries a write adds and withdraws.**

Both directions named, no whole-index reading available, and *replaced whole* is left to mean only what line 3 means by it. It also sits in the family: `landing` is the door, `reading` is what an agent has read, `calling` is a call answered — nouns naming a thing, not an act.

# Line 1 — the fault is the route, and required reading is the fix

*A body evaluates away from the path it lived at.*

You are right that it rests on a fact its reader has no route to, and you found the right fact: it is only true because every page import is type-only, which lives on `akasha-page-edge` — *An edge imports only a type, and is gone before the page runs.*

That is what required reading is for. *A domain's required reading names only the terms a reader would misread it without*, and this reader misreads this line without that one. → name `akasha-page-edge` in `requiredReadingSlugs`. Do not restate the fact here; you would be opening a second home for it, which is the thing we spent the evening closing.

Also, while it is open: **a body does not evaluate.** Something evaluates it, and the reader has to supply the missing actor. What the line is actually telling them is that the body outlives the path:

→ **A page's body can be loaded after the file it came from is gone.**

That is the fact the index depends on, in the order the reader needs it.

# Line 2 — hold it, and land it with the relation half

*Identity is settled for every page in a write before any relation is.*

Your instinct is right and the section rules say so plainly. `domain-design` takes *an invariant that holds now*. An ordering claim about relations, in a system with no relations in it, does not hold now — it is vacuously true, which is a promise wearing an invariant's clothes.

Not Intent either, before you reach for it: Intent takes a state the domain *should* be in, and this is not something you want to become true, it is something that will simply be true once the other half exists.

→ Cut it from this pass. Land it in the same commit as the relation half, where it becomes falsifiable the moment it is written. *Never add a piece for a case not here yet*, and this one is not here yet by your own account.

# Line 3

Keep as written. It is the clearest of the three, and it is a real Departure — replace-whole over append is exactly what a reader would undo to save a write.

So: definition reworded, line 1 rewritten with `akasha-page-edge` named, line 2 held, line 3 as is, and the parent's part list updated. That is a two-line page landing today and a third line landing when it can be wrong.
