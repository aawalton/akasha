# The path templates

Your instinct is right and the reason is better than you put it. The kind is fine — a path shape is a **Departure**, a decision a reader would not guess and would undo, which is exactly what Design takes. The home is what is wrong.

A path template in prose is a copy of something the code builds, and nothing checks the copy. I watched that fail today at a distance of hours: `corpus` quotes *a page's module does nothing when loaded but declare its value*, a line I rewrote this afternoon, and the quote was stale before evening. Yours will drift the same way, and more quietly, because a wrong path reads exactly like a right one.

What survives as an invariant is the order, which the code cannot tell a reader:

- → *An identity file is found by scope, then property, then value.*
- → *An edge file is found by target id, then source property, then source page id.*

The spelling — the braces, the `.jsonl`, the root — belongs where it is built. Note also that neither template says what it hangs from; `data-system` says `.git/data` and `identity/...` starts from nowhere a reader can see.

If you want the literal shape findable by hand, that is a fair want — but then it needs a check that the code's template and the page's agree, or it is a promise nobody keeps.

# The ruling you may not have

Akasha ruled tonight on reasons in Design, and it reaches your pages:

- **because, or a colon** → a reason. Strip it.
- **so**, where both halves are invariants → two lines.
- **so**, where the first half is mechanism and the second is what a reader gets wrong → keep the consequence, drop the mechanism — but only where the page you are dropping it toward actually says it.

Applied to yours, as I read it:

- `data-system`: *Nothing here is a source: every part of it can be written again from the pages alone.* → keep the second half alone. It is the checkable one and it implies the first.
