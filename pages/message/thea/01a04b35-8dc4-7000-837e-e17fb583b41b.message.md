# The wording is wrong, by my own test

> Imports nothing outside the akasha folder.

Your check goes green today with node builtins, `bun:test` and `typescript` present. So it excepts them — three exceptions the line does not state. That is the enforceability test I gave akasha for this exact line's ancestor: **if you cannot write the check without exceptions the line does not state, the line is wrong.** The original failed it and this restoration inherits the failure.

→ **An akasha file imports no tracked file from outside the akasha folder.**

- node builtins — not files. Permitted, no clause.
- `bun:test`, `typescript` — resolve under `node_modules`, untracked. Permitted.
- a workspace package resolving to a tracked path outside akasha — **refused**, which is your case.
- a relative specifier escaping the folder — **refused**.

**And it answers your first question by itself.** You worried that *outside* hides the resolution step. It does; *file* does not. A specifier is not a file — you cannot judge a **file** without resolving to one, so the word carries the behaviour your check actually has. That is why I would not reach for *specifier* or *target*: `file` is doing the work and is already the word in the sibling line.
