# Intent

- The code, instructions, memory, stories and books repositories are gone, and everything they tracked is tracked in akasha.
- The forked package pairs parked at `--from-code` and `--from-instructions` are one body each.
- Every reading reaches the pages where they stand, no code finding a page by naming the instructions root.
- All tracked files are in one repository.

# Notes

**The migration has one order and it is forced. The export standard is settled first, in `code` and `instructions` where the files still are, and only then does anything move.** There is no subset of packages that can go ahead, because the ones that would stay are reached by the ones that would go — `ops package move --all` refuses a partial plan and refuses rightly. The six packages already moved one at a time are in the broken intermediate state that predicts, and they come right when the rest follow. Why a package-at-a-time sweep has no unbroken intermediate state is bound by `finding/workspace-package/one-root-resolves-a-workspace-name`.

**The export standard is the largest obstacle.** `export-declared-here` fails a file exporting a name it did not declare, and 331 incoming files fail it, spread across 146 of the 281 packages — a little over half cannot land as written. 126 of them are `src/index.ts`, and the other 205 are ordinary files that happen to forward a name.

The 126 are one structural disagreement rather than 126 faults. A code package exposes a barrel because that is what an npm entry point is; akasha forbids forwarding, and the packages it already holds do without a barrel by naming subpaths in their `exports` map, `"./*": "./src/*.ts"`. Both patterns work; they cannot both be the pattern. Converting a barrel moves every call site that imported through it. The 205 are ordinary work: each is one file re-exporting a name it took from a neighbour, and the fix named in the refusal is to import from the declaring file at each call site.

A move is not authorship, and `page-type/mp-check` says nothing holds a body a program decided to a standard written for an author — an argument for letting the bodies land and paying the debt after. It is not one I get to act on: the same page states that a check binds every writer on every change and that a check replacing an old one still needs Alan's approval, and standing a check aside for a whole class of file is replacing it. So the 331 are work rather than an exemption.

**Barrel inventory.** Of the 99 barrels, 94 resolve completely: every name a barrel forwards traces to the module that declares it, following `export * from` transitively. Five cannot — `@shared/design-patterns`, `@shared/design-system`, `@shared/pages-access`, `@shared/pages-ui`, `@shared/utils-test` — and want reading rather than a tool. The call sites are 2,530 imports naming a package by its bare name against 3,611 already naming a subpath, so the pattern being converted to is already the majority one. Only 7 of the 2,530 are `import * as NS from` a workspace package, which cannot be split across modules and want deciding by hand; none is a default import. The order to convert in, and the trap under it, are bound by `finding/workspace-package/barrel-conversion-has-one-safe-order` and `finding/package-manifest/an-exports-map-is-a-whitelist`.

**Twenty-two forks to reconcile, plus `tsconfig.base.json`,** which both repositories claim at akasha's root and which every package's tsconfig extends. One workspace cannot hold two packages under one name, so each is an ablation rather than a move, and it happens at the moment the second repository's copy arrives to find the place taken. The verdicts, all reached by reading both copies:

- Decide themselves, byte-identical: `shared/errors-core`, `shared/pages-url`, `shared/supabase-auth`, `shared/supabase-database`, `temper/shared-foundation-misc-eso-paths-resolve`, `temper/shared-saved-variables`.
- To code: `shared/pages-query` (instructions is a strict subset missing the whole `askNaming` and `askShape` blocks), `shared/recurrence` (code's `reset-times.ts` is already an ablation shim re-exporting `akasha/day/day.ts`; instructions still carries the pre-ablation body), `temper/shared-build-deploy-checks` (110 files against a 2-file akasha vendor stub whose one source is identical), `temper/shared-foundation-misc-eso-paths`, `alanwalton/health-samples-access`.
- To instructions, each a strict superset with live importers the code copy cannot serve: `infra/k8s-types` (12 extra modules), `infra/k8s-synth` (`isSynthPath`), `shared/utils-fs` (`expandTilde`), `shared/utils-narrow` (`collapse`), `shared/supabase-server` (identical source, minus two unused `pg` dependencies).
- Genuine merges: `infra/ci-workflows`, `infra/scripts`, `infra/upscale` and `shared/utils-sync` are each two unrelated packages colliding on one name with zero identical source files between them; `temper/shared-build-deploy-addons-resolve` and `temper/shared-build-deploy-lua-runner` are real merges with a clean split of which copy contributes what.

`temper/shared-build-deploy-lua-runner` is a standing fault today, held at `instructions/packages/temper/shared/build-deploy/lua-runner` and at `akasha/lua-compiler/vendor/lua-runner` with genuinely different source in each. Why dates cannot adjudicate a fork is bound by `finding/instructions-repo/a-fork-can-be-live-in-the-tree-and-dead-in-every-code-path`.

**Three of the five incoming repositories hold no packages at all.** `memory`, `stories` and `books` carry 67,878 tracked files between them and not one `package.json`, `tsconfig.json` or `src/`. All three are page stores: `pages/<type>/<...>/<slug>.<type>.md` with `.jsonl` row sidecars. They come in as pages, and calling them packages would be a category error — there is nothing to build and no manifest to name.

**Paths naming the old places, to change together.** The sibling assumption is written three times: `akasha/repo/roots/roots.ts:27` (`BESIDE = resolve(HERE, "..", "instructions")`), `instructions/tools/lib/repo-roots.sh:5`, and `instructions/tools/lib/code-root.ts:6` — where instructions becomes a child of akasha, `repo-roots.sh:15-20` derives six roots that do not exist, silently and without error. Akasha names `"instructions"` as a repository in its own code in at least twelve files, including `akasha/page/repo-claim.ts:3`, where an unqualified path defaults to the instructions repo, and `akasha/page/page-types.ts:110`, where page types are scanned only under the instructions root. Outside the code: 34 systemd user units carry `WorkingDirectory=%h/repos/instructions` with relative `ExecStart`, generated by `instructions/tools/lib/service-unit.ts:65`; `instructions/settings/agents.json` carries 31 hardcoded `$HOME/repos/instructions` paths, one of them the `BASH_ENV` that fires on every Bash call in every agent; `instructions/settings/claude-config.json:4` holds the trust acceptance for the old directory; eleven dotfile symlinks point at absolute paths under `instructions/dotfiles`; and `akasha/editor-extension/dist/extension.js` has the shim path compiled in, so it needs rebuilding rather than editing. `INSTRUCTIONS_ROOT` must be exported and correct for the whole duration — see `finding/ops-cli/roots-resolve-at-import`.

**230 package pages carry `repo: code`,** and both implementations of the equality filter have to change in the same act, or a moved file is severed from its page under one and not the other. See `finding/pages-system/repo-key-is-an-equality-filter`.

**Instructions imports akasha TypeScript directly by relative path — 622 imports across 292 files — and akasha imports instructions never.** Landing the tree at exactly `akasha/tools/` leaves all 622 resolving by arithmetic coincidence, out of the repository and back in by name. That is a trap rather than a saving: invisible to a rename, and broken the moment the checkout is not named `akasha` at that depth.

**The layout is `<scope>/<name>`, one directory per package.** `@temper/game-items-addon` becomes `temper/game-items-addon`. That also costs less machinery: the code repository needs 183 explicit `workspaces` entries because its packages sit at varying depths, where a name-matched layout is `<scope>/*`.

**34 files still fail `file-length` after the exemptions landed,** and they are a case-by-case list rather than a class. Two `__fixtures__` Lua files at 1.88 MB and 1.03 MB, where `domain/code-comment` already treats `__fixtures__` as outside authored code and `isGeneratedFile` does not know it. Five vendored upstream k8s manifests, cloudnative-pg and cert-manager over 1 MB each. Seven game-data `.ts` files, `eidetic-book-data.ts` at 1.26 MB the largest, which are data written as source and want either a `.generated.ts` name or a different home. Eight addon XML files, several of them vendored ESO libraries. One `.d.ts`, one `server.py`, one 47 KB eso-typings manifest. And three initiative pages between 17 KB and 60 KB, where the ceiling is reporting rather than failing. The measurement behind the exemptions is bound by `finding/akasha-repo/checks-written-against-a-small-tree`.

**`code/packages/shared/status-bar-access` is the one true tsconfig capture** — its include of `../../../../akasha/**/*.ts` is about 640 files today and 7,640 once akasha holds everything. Narrowing the include is not the answer: the package's own page defines it as how Alan's readouts reach their numbers *from outside akasha*, and nothing is outside akasha at the end of this. What goes is the package rather than the glob, but something must still answer where those numbers come from, and that is an ablation to settle rather than a line to delete. The glob survey behind this is bound by `finding/ops-package/a-shrinking-exclude-is-a-capture`.

**The tray and the addons are one migration of 133 packages and 4,499 files.** `functionalType: "addon"` marks 70 packages whose workspace closure is 124 packages and 4,052 files; the watcher worker's closure is 34 packages, 25 of them already inside that set. `packages/temper/addons` is not addon source — it is the ambient ESO and library typings the addons compile against, plus the tsconfig that references them. All 147 tsconfigs under `packages/temper` reach outside their own package by relative path, 204 of those reaches into `packages/temper/addons`, and none of that coupling appears in the dependency graph, so the typings and the base config move ahead of every wave. The pinning that forced a six-wave order dissolves at this scope: 41 of the 148 packages in the tray-and-addon union were held by dependents outside it, and where every package moves there is no outside. The only remaining order is whatever keeps each intermediate state buildable.

How the mover behaves, and what it constrains about any further move, is bound by `finding/ops-package/survey-the-tracked-set`, `finding/ops-package/a-file-belongs-to-the-innermost-package` and `finding/ops-package/docker-copy-paths-are-build-context-paths`.
